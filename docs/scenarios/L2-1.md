# 场景 L2-1：终端设备频繁离线（轮询中断/重入循环）

> 模板：ADR-0002 场景拆解模板（14 层）| 分类：L2 设备在线维持 | 状态：**v1.1（官方依据 + 素材实证 + 自审修正：R2 验证通过；R1/R3 故障态待素材）**
> 官方依据：Silicon Labs 文档 + SDK（链接见各层）：
> - SED 轮询机制：docs.silabs.com「End Devices and Polling」（LONG_POLL keep-alive / SHORT_POLL 取消息 / Frame Pending）
> - End Device Poll Timeout：`EMBER_END_DEVICE_POLL_TIMEOUT`（默认 320s = 5×2⁶；超时未 poll → child 从父节点表移除, aged out）
> - 间接传输超时：`EMBER_INDIRECT_TRANSMISSION_TIMEOUT`（默认 7.68s, 父节点持有消息时长, SHORT_POLL 必须 < 此值）
> - 超时后机制：poll 无 ACK 达 `MAX_MISSED_POLLS` → rejoin 找新父；父节点收到超时 child 的 poll → 发 Network Leave Request（被踢重入循环）
> ⚠️ **状态声明**：判定规则框架由官方机制确认；**R2（Leave/Rejoin 循环）素材实证通过**；**R1（轮询超时）/R3（poll 无响应）无故障素材**（标注 **[待素材]**）。

---

## 0. 抓包可行性（数据现实层）— ✅ 已确认（含素材实测）

| 条件 | 要求 | 说明 |
|------|------|------|
| **最小抓包时长** | ≥ 一个 End Device Poll Timeout 窗口（默认 320s）才能观察"超时被移除" | R1 判定需覆盖 poll 间隔全貌；循环检测（R2）需覆盖 ≥2 轮 Leave/Rejoin |
| **sniffer 位置** | 父节点链路（SED 与父节点之间） | DataRequest 是 MAC 层单播（子→父）；sniffer 不在该链路则 poll 帧丢失 |
| **MAC 帧可见性** | **✅ 素材实测：DataRequest (MAC cmd 0x04) 可提取**（标准入网包 39 条） | pcap 路径 `parse_mac_frames` 已支持；cubx 路径需确认 MAC 命令帧保留 |
| **poll 间隔盲区** | 只看到 poll 发出，**看不到父节点侧是否超时**（child 表内部状态） | 间隔超阈值是推断依据，父节点实际移除行为需日志/后续帧佐证 |
| **静默离线盲区** | 设备彻底不 poll 且无 Leave → 无帧可抓 | 只能靠"该设备消息消失"推断（低置信） |

## 1. 场景识别（入口）

**用户描述关键词**：`频繁离线`、`掉线重连`、`时好时坏`、`一会儿在线一会儿离线`、`设备不稳定`、`老是掉线`、`在线状态闪烁`、`失联又恢复`

**典型症状**：
- 终端设备（尤其电池供电的 SED）反复 在线→离线→重入（网关面板上状态闪烁）
- 设备能入网但持续不了多久就掉线，随后自动重入
- 网关日志：`Child removed due to timeout` / `END_DEVICE_POLL_TIMEOUT` / 设备反复 rejoin
- 射频环境看似正常（Beacon/Assoc 都成功）

**与相邻场景的区分**（详见第 7 层）：
- 入网阶段失败（密钥/拒绝）→ **L1-3 / L1-4**
- 父节点主动移除（非超时）→ **L2-2 Child Table 老化**
- Orphan 孤立 → **L2-3**
- 路由器掉线带垮子设备 → **L2-4**

## 2. 正常抓包基线 — ✅ 官方机制 + 健康素材实测

**SED 轮询机制**（官方，docs.silabs.com End Devices and Polling）：
```
SED (睡眠终端) 周期性 poll 父节点 (MAC Data Request):
  - LONG_POLL: 空闲期 keep-alive 轮询 (应 < End Device Poll Timeout 320s, 否则被父节点移除)
  - SHORT_POLL: 有消息事务时快速轮询 (<7.68s 间接传输超时, 保证取到父节点缓存消息)
父节点: MAC ACK 带 Frame Pending 位 → 有缓存消息时 SED 继续 poll 取数据
keep-alive 失效链 (官方):
  poll 间隔 > 320s → 父节点 child 表移除 (aged out)
  → 设备再 poll → 父节点发 Network Leave Request → 设备 leave → rejoin 找新父
  → (循环) = 频繁离线
```

**健康素材实测**（1-标准入网抓包-2, SED 轮询）：39 条 DataRequest，poll 间隔 **0.1-5.5s**（短轮询密集 + 长轮询 5.5s），全包 0 Leave/Rejoin —— 轮询节奏正常。

**官方配置参照**（本地 SDK 源码, end-device-support-config.h / sl_zigbee_pro_stack_config.h）：
- LONG_POLL 默认 **300s**（`EMBER_AF_PLUGIN_END_DEVICE_SUPPORT_LONG_POLL_INTERVAL_SECONDS`）
- End Device Poll Timeout 默认 **256 分钟**（`EMBER_END_DEVICE_POLL_TIMEOUT MINUTES_256`, R21 标准值; 配置范围 SECONDS_10 ~ MINUTES_16384）
- ⚠️ **R21 变更**（EmberZNet 6.5.0 RN）：旧 SDK 默认 ~5 分钟（320s），R21 起改为 256 分钟
- SHORT_POLL 默认 1s / Wake Timeout 3s / MAX_MISSED_POLLS 默认 3

## 3. 异常表现 — [官方确认, R1/R3 帧序列待素材]

| 观察点 | 正常 | 异常（本场景） |
|--------|------|----------------|
| poll 间隔 | 远小于父节点 Poll Timeout（健康实测 ≤5.5s; LONG_POLL 默认 300s） | **≥ 父节点 Poll Timeout**（配置项 10s~16384min; 检测器用 256min 默认）→ R1 |
| Leave (rejoin=1) | 无 | **同一设备反复**（自发或 TC 指令）→ R2 循环 |
| Rejoin 帧 | 无 | 反复出现（设备找新父）→ R2 佐证 |
| poll 无 ACK | 每次 poll 有 MAC ACK | **连续多次无 ACK**（≥ MAX_MISSED_POLLS）→ R3 |
| 设备在线状态 | 持续在线 | 网关面板反复 在线↔离线 |

**R2 循环形态（素材实证, 中继入网抓包）**：TC 对 0x737D 反复发 rejoin=1 Leave ×336（跨 34s）——被要求重入的循环；设备自发的 rejoin=1 Leave 循环 [待素材]。

## 4. 判定条件（可编程规则）— 规则框架已确认（grilling 定稿 2026-08-05），R1/R3 阈值待素材

```
规则 L2-1-R1（轮询中断, 高置信, 官方配置项）:
  设备为终端 (有 DataRequest poll 活动)
  AND 同设备 poll 间隔最大值 ≥ 父节点 End Device Poll Timeout
      (配置项 SECONDS_10~MINUTES_16384; 检测器用 R21 默认 256min=15360s [保守, 待素材校准])
  → L2-1 命中 (根因: 父节点超时移除 child → 设备 aged out)
    官方: EMBER_END_DEVICE_POLL_TIMEOUT; poll 间隔超过即被移除
    ⚠️ 【v1.1 自审修正】v1.0 用 320s (旧 SDK 默认 ~5min) 是错的:
       - R21 起默认 256 分钟 (EmberZNet 6.5.0 RN 官方)
       - 健康 LONG_POLL 默认 300s — 320s 阈值会把健康设备误判
       - 实际判定需知道父节点配置值 (抓包不可见, 配置相关)
    【v1.1】无故障素材, 阈值 15360s (256min 保守默认) [待素材校准]

规则 L2-1-R2a（自发重入循环, 高置信, 官方机制确认）:
  同设备 rejoin=1 Leave (设备自发) ≥2 次 (跨轮)
  AND (Rejoin 帧出现 或 设备再次 Assoc/Announce)
  → L2-1 命中 (根因: 设备睡眠/电源/配置问题导致反复掉线重入)
    【v1.0】设备自发的循环素材 [待素材]

规则 L2-1-R2b（被踢重入循环, 中置信, 素材实证 2026-08-05）:
  TC (0x0000) 对同一设备反复发 rejoin=1 Leave ≥2 轮 (跨 >5s 窗口)
  → L2-1 命中 (根因: 父节点/TC 反复要求设备重入 — child 表超时后 poll 触发)
    素材: 中继入网抓包 TC→0x737D rejoin=1 Leave ×336 (34s)
    与 L1-4 区分: L1-4 = 单次踢人/拒绝; R2b = 反复 rejoin=1 循环 (允许重入的循环)

规则 L2-1-R3（poll 无响应, 中置信, 官方机制确认）:
  设备 DataRequest 发出
  AND 连续无 MAC ACK ≥ MAX_MISSED_POLLS (默认 3, EMBER_AF_PLUGIN_END_DEVICE_SUPPORT_MAX_MISSED_POLLS [待校准])
  AND 设备随后 Rejoin
  → L2-1 命中 (根因: 射频/父节点问题 — 设备收不到 ACK 自行 rejoin)
    【v1.0】无故障素材 [待素材]
```

**关键字段**（官方确认）：
- Data Request：MAC 命令 cmd_id=0x04（子→父单播）
- Leave：NWK cmd 0x04，rejoin 标志位（0x20 掩码, 行为实证确认）
- Rejoin Request/Response：NWK cmd 0x06/0x07
- MAC ACK：poll 的响应（Frame Pending 位在 MAC FCF）

## 5. 直接证据（铁证）— ✅ 官方确认

| 优先级 | 证据 | 说明 |
|--------|------|------|
| ★★★ | 同设备 poll 间隔 ≥ 父节点 Poll Timeout（配置项, 默认 256min） | 官方 EMBER_END_DEVICE_POLL_TIMEOUT → **R1**（待素材, 配置相关） |
| ★★★ | 同设备 rejoin=1 Leave ≥2 轮（自发或 TC 指令） | 官方机制链（超时→Leave→rejoin 循环）→ **R2** |
| ★★★ | 反复 Rejoin 帧 | 设备找新父的直接证据（R2 佐证） |
| ★★ | poll 连续无 MAC ACK ≥ MAX_MISSED_POLLS | 官方：无 ACK 达阈值 → 设备 rejoin → **R3**（待素材） |
| ★★ | 被踢重入循环（TC rejoin=1 Leave 反复） | 素材实证：737D ×336（中继入网抓包）→ R2b |

## 6. 根因链路 — [官方部分确认]

```
表象: 设备反复 在线→离线→重入
  ├─ 直接原因 1: 轮询间隔超过父节点超时 (≥320s)
  │    ├─ 深层: LONG_POLL 配置错误 (睡眠过长) / 电池电量低 / 设备死机后唤醒
  │    ├─ 深层: 父节点 Poll Timeout 配置过短 (非默认 320s)
  │    └─ 表现: R1 (间隔超阈值)
  ├─ 直接原因 2: poll 无响应 → 设备自行 rejoin
  │    ├─ 深层: 射频链路差 (关联 L3-9/L7-2) / 父节点忙 / 干扰
  │    └─ 表现: R3 (连续无 ACK + Rejoin)
  ├─ 直接原因 3: 父节点超时移除后循环
  │    ├─ 深层: 超时 child 再 poll → 父节点发 Network Leave → 重入 → 再超时 (循环)
  │    ├─ 深层: TC/父节点反复要求重入 (child 表状态与设备不同步)
  │    └─ 表现: R2 (Leave/Rejoin 循环, 含 737D 素材形态)
  └─ 交叉: 与 L1-4 区分 — 单次踢人 vs 反复循环; 与 L2-2/2-3 关联 (child 老化/Orphan)
```

## 7. 混淆项（长得像但不是）— [骨架]

| 混淆场景 | 抓包差异 | 排除方法 |
|----------|----------|----------|
| **L1-4 TC 拒绝/踢人** | 单次/少量 Mgmt Leave Req / 0x07 / rejoin=0 踢人 | R2b 是 **rejoin=1 反复循环**（允许重入）；L1-4 是拒绝/单次移除 |
| **L1-3 密钥循环** | 838D 形态：VerifyKey 重发 + Confirm 收不到（密钥事务内循环） | 看是否密钥事务帧（0x0F/0x10）循环 vs Leave/Rejoin 循环 |
| **L2-2 Child Table 老化** | 父节点主动移除（无 poll 超时证据） | 看 poll 间隔是否超 320s（R1） |
| **L2-3 Orphan/Rejoin 循环** | Orphan 通知为主（无 poll 活动） | 看是否有 poll 活动：有 → L2-1；无 → L2-3 |
| **设备主动永久离网** | rejoin=0 Leave（不回来） | rejoin=0 → 排除本场景（非循环） |
| **健康 SED** | poll 间隔正常（≤5.5s 实测）+ 无 Leave | 间隔 + 无循环 → 排除 |

## 8. 自动检测盲区 — [官方确认]

| 盲区类型 | 本场景表现 | 后果 |
|----------|-----------|------|
| **child 表内部状态** | 抓包看不到父节点是否已超时移除 | R1 靠间隔推断；父节点实际行为需日志/后续帧 |
| **Poll Timeout 配置盲区** | 父节点配置值抓包不可见（SECONDS_10~MINUTES_16384, 无线上协商） | R1 阈值依赖配置知识；检测器用 256min 保守默认，命中需人工确认配置 |
| **poll 帧可见性** | DataRequest 是 MAC 单播，sniffer 不在链路则丢 | poll 统计不准 → R1/R3 不可判定 |
| **静默离线** | 设备彻底停 poll 且无 Leave → 无帧 | 只能靠消息消失推断（低置信） |
| **抓包时长** | 超时窗口要求长抓包（256min 默认） | 短抓包漏 R1（间隔超阈值看不到） |
| **MAX_MISSED_POLLS 值** | 官方文档无默认值（插件配置） | R3 阈值 [待校准] |

## 9. 置信度分级 — [框架确认]

| 置信度 | 判定条件 | 复核建议 |
|--------|----------|----------|
| **高** | R1（poll 间隔 ≥320s）+ 设备后续失联/Leave；R2a（自发 rejoin=1 循环 + Rejoin 帧） | 直接定位（轮询配置/电池/父节点超时配置） |
| **中** | R2b（TC 反复 rejoin=1 Leave）；R3（poll 无 ACK + Rejoin） | 查父节点/TC 日志（超时移除原因）；现场射频 |
| **低** | 静默离线（无 poll 无 Leave，设备消息消失） | 补长抓包；查设备侧日志 |
| **不可判定** | sniffer 不在 poll 链路 / 抓包 <320s 窗口 | 需按第 0 层条件重抓 |

## 10. 人工复核清单 — [框架确认]

- [ ] poll 间隔是否 ≥320s（R1）— 长抓包统计间隔分布
- [ ] Leave 是否 rejoin=1 且反复（R2）— 自发 vs TC 指令（方向区分）
- [ ] Rejoin 帧是否出现（R2 佐证）
- [ ] poll 是否有 MAC ACK（R3）— 连续无 ACK 次数
- [ ] 父节点/TC 日志：超时移除、Leave Request 原因
- [ ] 设备侧：LONG_POLL 配置、电池、睡眠模式
- [ ] 排除：L1-4（单次踢人）、L1-3（密钥循环）、L2-2/2-3

### 示例 A：健康 SED 轮询基线 ✅（1-标准入网抓包-2）

```

全包 0 Leave / 0 Rejoin
```

### 示例 B：规则 R2b — 被踢重入循环 ✅（中继入网抓包(1).cubx, TC→0x737D, 2026-08-05 实证）

```

→ L2-1-R2b 命中 (TC 反复要求设备重入 — child 表超时后 poll 触发的循环)
⚠️ 注意: 该素材主场景是 L1-3 (838D 密钥循环) + L3-5 (源路由), 737D 循环是素材内
   附带发现的 L2-1 形态 — 素材交叉验证
```

### 示例 C：（待素材）规则 R1 / R2a / R3

**R1 条件**：同设备 poll 间隔 ≥ 父节点 Poll Timeout（默认 256min）+ 后续失联。
**R2a 条件**：设备自发 rejoin=1 Leave ≥2 轮 + Rejoin。
**R3 条件**：poll 连续无 ACK ≥3 次（官方默认）+ 设备 Rejoin。
**候选素材**：终端频繁离线场景抓包（需覆盖超时窗口 + poll 链路）。

## 自审修正 (2026-08-05, v1.1)

用户要求结合 MCP 工具诚实自审, 发现并修正:

1. **🔴 R1 阈值 320s 错误**（v1.0）: 320s 是**旧 SDK (R21 前) 默认 ~5 分钟**。
   官方 EmberZNet 6.5.0 RN: "default has been changed to the 256 Minute default from R21";
   本地 SDK: `EMBER_END_DEVICE_POLL_TIMEOUT MINUTES_256`。且健康 LONG_POLL 默认 300s —
   320s 阈值会把健康设备误判。修正: 阈值 = 配置项 (10s~16384min), 检测器用 256min 保守默认。
2. **✅ MAX_MISSED_POLLS=3 有源码依据**: 本地 SDK end-device-support-config.h
   `#define EMBER_AF_PLUGIN_END_DEVICE_SUPPORT_MAX_MISSED_POLLS 3` — v1.0 标注 [待校准] 过保守。
3. **✅ R2b 机制链官方确认**: message 检索官方文档 "parent node will ask the end device to
   leave and rejoin if it receives a mac data poll from the end device which doesn't exist in
   the child table" — TC 反复 rejoin=1 Leave = 反复收到超时 child poll。但素材缺 poll 帧
   直接证据 (737D 素材无 MAC 层 poll), 已标注。
4. **示例素材现状**: 目前无"终端频繁离线"正例素材 — 示例 B (737D) 是 TC 指令循环 (机制
   成立, 非设备自发离线直接证据); R1/R2a/R3 正例均 [待素材]。
