## 理论依据 (Silicon Labs 官方文档, 2026-08-21 MCP 检索, 勿重复)

| 证据 | 官方依据 (引用) | 强度 |
|------|----------------|------|
| poll 目标 = 父节点 | docs.silabs.com zigbee-concepts-network/end-devices: "Polling is the event wherein an end device sends a data request message to **its parent node**"; "Mac Data Polling is used as the keep-alive message between the **child and parent**"; "End devices communicate **only through their parent nodes**" | 铁证: SED 只向父 poll, MAC Data Req 的 dst = 父节点 |
| Route Record relays | docs.silabs.com many-to-one: "The route record command frame lists the short IDs of the **relays that were used along the route** from the source to us"; "When node 0x1002 relays the Route Record, it **adds itself** to the Route Record"; gecko_sdk message.h: "relay closest to the source is listed first" | 铁证: 每跳实际经过的中继 |
| AssocResp = 父 | Zigbee 规范: 关联响应由父节点发出, 入网即绑定父子关系 (素材实证: 中继入网抓包 Assoc 流程) | 铁证 |
| Route Reply | Zigbee 规范 3.5.3 路由发现响应含路径 (补充证据, 细节待实现时核对) | 补充 |
| Link Status | 物理邻居表维护 (非转发证据) — 降级为辅助信息, 不当中继边 | 降级 |

## 当前代码问题 (总控已定位)

`backend/topology.py`:
- **220-239 行"推断父子"启发式**: 节点与 coord 通信多 → 直连; 其余找通信最多的已知 parent —
  **无协议依据**。Zigbee 中 SED 经中继与 coord 通信 (通信多 ≠ 直接相连), 中继设备也大量转发 —
  → **错判根源**
- **26 行 link_status_neighbors**: 邻居 (物理可达) 被当链路画 → 混淆 (邻居 ≠ 实际转发中继)
- **56-106 行 Route Record 路径**: 唯一严谨依据, 但只覆盖源路由流量 → 非源路由时漏判
- poll 帧 (mac_cmd_id=4) 在 _full_packets 中有 (U7 已实证), 但未用于链路判断

## 实现要点 (总控设计)

### 1. 链路证据采集 — backend/topology.py 重构
- **新增 `_build_link_evidence(packets, full_packets) -> dict`** (替代 220-239 启发式):
  - **poll 目标**: full_packets 中 mac_cmd_id=4 的帧, mac_dst = 发送者父节点 (证据强度高,
    持续 poll 目标稳定 = 父节点; 目标变化 = 换父事件)
  - **AssocResp**: mac_cmd_id=2 的帧, 目标短地址 = 入网设备, 源 = 父节点 (入网时刻)
  - **Route Record relays**: 已有 route_record_relays, 每对相邻 relay 之间 = 中继边
  - **Route Reply**: 已有 route_reply (originator/responder), 补充路径证据
  - 每条证据带: 类型 (poll/assoc/rr/rreply)、时间戳、强度 — 供链路变化时间轴使用
- **链路边定义**: 只画有协议证据的边; 边属性: 证据类型/时间范围/变化次数
- **Link Status 降级**: 保留邻居显示 (现样式), 标记"物理邻居"非"中继链路", 不再参与
  父子推断
- **删除**: 220-239 行通信量推断父子逻辑 + parents/children 启发式

### 2. 链路变化时间轴 — 前端 topo.js + 后端 API
- **后端**: 新端点或 /api/topology/graph 扩展 — 每节点返回 `link_history`:
  `[{ts, from_parent, to_parent, evidence}]` (poll 目标变化/assoc/rejoin 事件)
- **前端**: 选节点 → 时间轴条显示链路变化事件点 (换父/重连/断开) → 点击/拖滑块
  定位到该时刻 → 图上显示该时刻链路 (高亮) + 前后对比 (旧链路虚线/新链路实线,
  变化节点高亮)
- 去掉播放按钮 (playTO/定时器/▶ 控件/自动推进逻辑); 时间滑块保留
- 时间轴实现: 复用现有 timebar 区域改造 (节点选中后出现链路事件轴)

### 3. UI 不变项
- 布局/形状分类/图例/邻居边样式/路径色 — 全部不动

## 风险

- Route Record 覆盖有限素材: 边可能比现在少 (诚实: 无证据的边不画) — 需与用户确认
  "宁可少画不错画"原则 (链路信息视图下这是正确方向)
- poll 帧量大 (SED 每秒 poll): 证据聚合按 (设备, 父) 时间段折叠, 不逐帧存
- 换父事件判定: poll 目标变化 + 时间窗 (防瞬时抖动误判)
- 前端改动集中 topo.js (927 行), 注意与 U5/U7 时间过滤联动不破坏
