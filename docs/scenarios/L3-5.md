# 场景 L3-5：源路由/MTORR 失效（下行链路断）

> 模板：ADR-0002 场景拆解模板（14 层）| 分类：L3 运营期核心 | 状态：**v1.0（官方依据 + 真实素材实证：R1 验证通过；R2/0x0C 故障态待素材）**
> 官方依据：Silicon Labs 文档 + SDK 源码（链接见各层）：
> - route error 语义：`message.h` `sl_zigbee_incoming_route_error_handler`（0x0B/0x0C 仅 concentrator 模式发生；断链前一跳生成并沿 MTORR 回传；**3 连发 = 单次失败 APS 重试预期行为**）
> - 错误码枚举：`stack-info.h`（0x0B=SOURCE_ROUTE_FAILURE, 0x0C=MANY_TO_ONE_ROUTE_FAILURE）
> - MTORR/源路由机制：docs.silabs.com「Many-to-One and Source Routing」（MTORR 广播 → 上行路由 → Route Record → 源路由表反转）
> - 自愈机制：Concentrator Plugin（route error 计数超阈值 → 重发 MTORR 重建路由）
> ⚠️ **状态声明**：本场景**判定规则框架**已由官方依据 + 838D 真实素材（39 条 0x0B）双重确认；**R2（0x0C MTORR 上行失败）无故障素材**（标注 **[待素材]**）。

## 0. 抓包可行性（数据现实层）— ✅ 已确认（含素材实测）

| 条件 | 要求 | 说明 |
|------|------|------|
| **最小抓包时长** | 覆盖多轮失败（≥2 轮，素材中一轮 ~0.5-3s）+ 观察自愈尝试（MTORR 周期默认 60s） | 素材实测：13 轮失败跨 34s；判定 ≥2 轮约需 ≥3-5s 连续抓包 |
| **sniffer 位置** | **断链处链路**（素材：中继 1885↔838D） | 0x0B 由断链前一跳生成（素材实证：39 条全 src=0x1885）；sniffer 不在该链路则看不到 |
| **捕获信道** | 与网络信道一致 | — |
| **命令帧可见性** | **✅ 素材实测：Network Status 命令明文可读**（0x0B + target 短地址） | 838D 素材 cubx 解析直接读出 code=0x0B, target=0x838D |
| **断链定位盲区** | 0x0B 只告诉你"断链前一跳是谁"（src），**不告诉你断链本身在哪一跳** | 需结合 Route Record（历史下行路径）推断断链点；多跳网络单 sniffer 覆盖不全时不可判定 |
| **MTORR 帧盲区** | MTORR 是广播（全网络），单 sniffer 可抓 | 素材实测 161 条 Route Request（含 MTORR 重广播）可见 |

## 1. 场景识别（入口）

**用户描述关键词**：`下行不通`、`控制不了设备`、`网关发命令失败`、`SOURCE_ROUTE_FAILURE`、`0x0B`、`route error`、`源路由失败`、`中继转发失败`、`命令超时`、`设备收不到命令但能上报`

**典型症状**：
- 设备能上报（上行通），但网关发命令设备收不到（下行断）——**非对称链路**
- 网关日志：`EMBER_SOURCE_ROUTE_FAILURE (0x0B)` / `sl_zigbee_incoming_route_error_handler`
- 用户观测：838D 案例"入网后立即被踢"表象下，根因是 Confirm 经中继 1885 源路由转发全部失败
- 设备侧：收不到网关任何下发（但上行上报正常）

**与相邻场景的区分**（详见第 7 层）：
- 传统表路由失败（非 concentrator 场景）→ **L3-6 路由校验失败**（0x0A）等
- 密钥验证失败被踢 → **L1-3-B2**（无 0x0B，NWK Leave 路径）
- 密钥验证循环 + 源路由失败 → **L1-3-B2-LOOP-ROUTE**（本场景的 L1 表象，交叉双报）

## 2. 正常抓包基线 — ✅ 官方流程确认

**MTORR/源路由建立流程**（官方，docs.silabs.com Many-to-One and Source Routing）：
```
① Concentrator 广播 MTORR (Route Request, many-to-one 标志, path cost 从 0 累加)
   → 所有 router 建立"回 concentrator"的上行路由表项
② Router 上行单播前, 先发 Route Record (记录经过的 relay 链)
   → concentrator 收到后**反转 relay list** 存入源路由表
③ Concentrator 下行单播 = 源路由帧 (NWK 头带 relay list + relay index)
   → 中继按源路由表转发, 不查本地路由表
④ 路由维护: concentrator 周期性重发 MTORR (插件默认 60s)
```

**健康基线（自愈闭环，官方 Concentrator Plugin）**：
- 偶发断链 → route error (0x0B) ×3（单次 APS 重试的预期行为）
- Concentrator 计数超阈值 → **重发 MTORR** → router 上行时发新 Route Record → 源路由表更新 → 链路恢复
- 健康网络: 0x0B 短暂出现（≤1 轮）后伴随 MTORR/Route Record 更新，无持续失败

**健康素材实测参考**（1-标准入网抓包-2）：全包 0 条 Network Status（L1-3.md 第 2 层），干净健康基线。

## 3. 异常表现 — [官方确认 + 838D 素材实证]

| 观察点 | 正常 | 异常（本场景） |
|--------|------|----------------|
| Network Status 0x0B (Source Route Failure) | 偶发 ≤1 轮（3 连发） | **≥2 轮持续**（同 target）— 素材：39 条 = 13 轮，34s |
| 0x0B 的 src | 断链前一跳（随机） | **固定同一中继**（素材：39 条全 src=0x1885）— 断链点固定 |
| 0x0B 的 target | 任意 | **固定同一目标设备**（素材：全 target=0x838D）— 下行到该设备持续失败 |
| 自愈迹象 | route error 后 MTORR 重广播 + 新 Route Record | 素材：161 条 Route Request 但 0x0B 持续 34s — **自愈尝试失败** |
| 设备侧 | 收到网关下发 | 收不到任何源路由单播（上行上报正常）— 非对称 |
| 伴随 L1-3 | — | 素材：838D 密钥验证循环（Confirm 收不到 → VerifyKey 重发）— **交叉现象** |

## 4. 判定条件（可编程规则）— 规则框架已确认（grilling 定稿 2026-08-04），0x0C 阈值待素材

```
规则 L3-5-R1（源路由下行失败, 高置信, 官方 + 838D 素材实证）:
  network_status (0x03) 出现, code == 0x0B (Source Route Failure)
  AND 按 target 分组: 同 target 的 0x0B 按时间间隔 <0.5s 归为同轮 (APS 重试 3 连发 = 1 轮)
  AND 轮数 ≥ 2 (即 ≥6 条 或 跨多轮的 0x0B)
  → L3-5 命中 (根因: concentrator 源路由表指向的中继链路断 / 目标设备移动 / 中继 child 表失效)
    官方语义: 0x0B 仅 concentrator (MTORR 上行 + 源路由下行) 模式发生;
              断链前一跳生成 route error 并沿 MTORR 回传
    素材: 中继入网抓包 838D — 39 条 0x0B 全 src=0x1885 → target=0x838D, 13 轮, 34s
    【单轮不判定】≤1 轮 (≤3 条) = 单次失败 APS 重试的预期行为 (message.h 官方注释)

规则 L3-5-R2（MTORR 上行失败, 中置信, 官方语义确认）:
  network_status 出现, code == 0x0C (Many-to-One Route Failure)
  AND 同 target ≥2 轮 (分组同 R1)
  → L3-5 命中 (根因: 上行 MTORR 链路断 — 设备上报失败)
    【v1.0】无故障素材, 阈值沿用 R1 框架 [待素材]

规则 L3-5-EX（排除/健康）:
  无 0x0B/0x0C → 排除
  0x0B ≤1 轮 (≤3 条, 间隔 <0.5s 内) → 健康瞬态 (不判定)
```

**关键字段**（官方确认）：
- Network Status：NWK cmd 0x03；payload `[code(1)][target(2 LE)]`；code 0x0B=Source Route Failure, 0x0C=Many-to-One Route Failure（stack-info.h 枚举）
- 0x0B 的 **src = 断链前一跳**（素材实证：0x1885 中继）；target = 下行目标设备
- 轮分组依据：message.h 官方注释 "three route error messages in succession for a single failed retried APS unicast"

## 5. 直接证据（铁证）— ✅ 官方确认 + 素材实证

| 优先级 | 证据 | 说明 |
|--------|------|------|
| ★★★ | **Network Status code=0x0B，同 target ≥2 轮** | 官方：源路由单播断链；concentrator 专属 → **R1** |
| ★★★ | 0x0B 固定 src=同一中继 + 固定 target=同一设备 | 素材实证 39 条全 1885→838D — 断链点固定，非随机 |
| ★★★ | 持续失败超自愈窗口（0x0B 跨 >10s 仍无恢复） | 素材：34s 持续；健康网络自愈闭环（MTORR+Route Record） |
| ★★ | concentrator 重发 MTORR 但链路未恢复 | 素材：161 条 Route Request（含 MTORR）仍失败 — 自愈失败 |
| ★★ | 伴随 L1-3 密钥循环（同 target） | 838D 案例：Confirm 收不到 → VerifyKey 重发 — 交叉现象 |
| ★★ | Network Status code=0x0C | 官方：MTORR 上行断链 → **R2**（待素材） |

## 6. 根因链路 — [官方部分确认]

```
表象: 下行命令失败 / 设备收不到下发 (上行正常) / "入网后被踢"假象 (838D)
  ├─ 直接原因 1: 源路由表指向的链路断 (0x0B 持续 ≥2 轮)
  │    ├─ 深层: 中继↔目标设备射频链路断 (干扰/移动/低电量) — 关联 L3-9 非对称 / L7-2
  │    ├─ 深层: 中继 child 表失效 (目标设备已迁移但源路由表未更新) — 关联 L2-2
  │    ├─ 深层: 源路由表过期 (concentrator 重启丢表 / LowRam 淘汰) — 官方 KBA
  │    └─ 表现: 规则 R1 (0x0B 持续)
  ├─ 直接原因 2: 上行 MTORR 链路断 (0x0C) → 设备上报失败
  │    └─ 表现: 规则 R2 (0x0C, 待素材)
  ├─ 直接原因 3: 自愈机制失效
  │    ├─ 深层: Concentrator Plugin 阈值未触发 / MTORR 广播被淹没
  │    └─ 表现: 0x0B 持续但无有效 MTORR/Route Record 更新 (素材实证: 161 条 RR 未恢复)
  └─ 交叉: L1-3-B2-LOOP-ROUTE (密钥验证循环) = 本场景的 L1 表象
       └─ 官方: Confirm 经断链中继转发失败 → 设备重发 VerifyKey → 误判为密钥问题
```

## 7. 混淆项（长得像但不是）— [骨架]

| 混淆场景 | 抓包差异 | 排除方法 |
|----------|----------|----------|
| **L1-3-B2-LOOP-ROUTE（密钥循环）** | 无 0x0B 或 0x0B ≤1 轮；TCLK 验证循环为主 | 看 0x0B 轮数：持续 ≥2 轮 → 根因 L3-5（交叉提示）；否则 L1-3 |
| **L3-6 路由校验失败** | code=0x0A (Validate Route)，传统表路由 | code 区分：0x0A vs 0x0B/0x0C |
| **L3-8 目标不可达** | code=0x07/0x08 (Target Unavailable/Unallocated) | code 区分 |
| **L3-9 非对称链路** | 无 0x0B 持续；Link Status in/out cost 不对称 | 看 0x0B 是否持续 + Link Status 邻居表 |
| **健康瞬态** | 0x0B ≤1 轮（≤3 条，<0.5s 内） | 轮数 <2 → 不判定（官方：单次重试预期） |
| **SED 睡眠轮询丢失** | 无 0x0B；MAC Data Request 无响应 | 无 Network Status → 排除本场景 |

## 8. 自动检测盲区 — [官方确认]

| 盲区类型 | 本场景表现 | 后果 |
|----------|-----------|------|
| **断链点定位** | 0x0B 只报"断链前一跳"（src），断链本身发生在 src 与 target 之间 | 单 sniffer 无法定位具体断链点；需 Route Record 对照 + 现场信息 |
| **抓包未覆盖** | 0x0B 由断链前一跳生成；sniffer 不在该链路则全部丢失 | 判为"无 0x0B"→ 误报健康（不可判定需声明） |
| **设备未听到** | 源路由帧已发出但 target 未收到（0x0B 由中继生成，sniffer 抓到 ≠ 中继真失败） | 0x0B 本身是断链实证（中继侧判定），可接受；但断链原因（射频 vs child 表）需现场 |
| **route error 也可能丢失** | 官方：不保证 route error 送达（message.h） | 0x0B 缺失 ≠ 无失败；APS 重试计数是唯一确定途径（抓包侧不可见） |
| **0x0C 上行失败** | 上行链路失败在网关侧不产生本地帧（需断链处 sniffer） | R2 依赖断链处抓包，素材难获取 |

## 9. 置信度分级 — [框架确认]

| 置信度 | 判定条件 | 复核建议 |
|--------|----------|----------|
| **高** | 同 target 0x0B ≥2 轮 + 固定 src 中继 + 持续跨自愈窗口（+ 可选伴随 L1-3 交叉） | 直接定位断链链路（中继↔设备），查现场射频/移动/child 表 |
| **中** | 0x0B ≥2 轮但无 L1-3 交叉/无 MTORR 自愈观察 | 补抓包覆盖自愈窗口；查 concentrator 配置（阈值/类型） |
| **低** | 0x0B 1-2 轮边界（素材差异浮动） | 补抓包确认轮数 |
| **不可判定** | sniffer 不在断链链路 / 无 Network Status 但怀疑下行失败 | 需断链处抓包 |

## 10. 人工复核清单 — [框架确认]

- [ ] Network Status 是否 code=0x0B / 0x0C（非 0x0A/0x07/0x08 等其他错误码）
- [ ] 0x0B 轮数：同 target 按 <0.5s 间隔分组是否 ≥2 轮（≤1 轮 = 健康瞬态）
- [ ] 0x0B 的 src 是否固定（同一断链前一跳）— 固定 = 断链点确定
- [ ] 自愈观察：route error 后是否有 MTORR 重广播 + 新 Route Record（有 = 自愈尝试, 无 = 插件阈值未触发）
- [ ] 伴随现象：同 target 是否同时命中 L1-3（密钥循环 = 表象/根因交叉）
- [ ] 现场：中继↔目标设备射频环境（距离/遮挡/干扰）、目标设备是否移动、中继是否重启
- [ ] concentrator 配置：Concentrator Type（High/LowRam）、Route Error Threshold、MTORR 周期

## 12. 判定示例（真实抓包）— 示例 A ✅ 素材实证 / 示例 B 待素材

### 示例 A：规则 R1 — 源路由持续失败 ✅（中继入网抓包(1).cubx, 838D, 2026-08-04 实证）

**网络构成**（用户确认）：网关(协调器)=concentrator 0x0000 / 中继 1885=外购 / 838D=自家设备（Telink OUI）。

**实测帧序列**（cubx 解析，Network Status 明文）：
```
t=1780364679.4  Network Status ×N: 全 39 条 code=0x0B, src=0x1885, target=0x838D
                时间跨度 34s (1780364679.4-1780364713.3)
                轮分组: 间隔 3-10ms 密集 (APS 重试 3 连发 = 1 轮), 跨轮间隔 0.97/1.6/27.8s
                → 13 轮持续失败
伴随: Route Request ×161 (含 MTORR 重广播, 自愈尝试) + Route Record ×31 — 链路未恢复
交叉: L1-3-B2-LOOP (838D VerifyKey 循环) — Confirm 经 1885 转发失败, 设备收不到确认
→ 规则 L3-5-R1 命中 (≥2 轮, 高置信) + L1-3 交叉提示
→ 根因结论 (与 L1-3 第 12 层一致): 中继 1885 到 838D 的下行源路由链路断,
  密钥内容/协议正常 — 非密钥问题, 是 L3 路由层问题
```

### 示例 B：（待素材）规则 R2 — MTORR 上行失败 (0x0C)

**条件**：Network Status code=0x0C（同 target ≥2 轮）。
**候选素材**：需在断链链路上抓包（上行失败场景）。
