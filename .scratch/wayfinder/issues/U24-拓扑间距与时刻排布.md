**What to build:** ① 修"节点距离太大 → 默认 fit 把字号/节点缩得很小、观感稀疏";
② 修"节点关系变了但圆环位置不变"（排布要反映该时刻的链路结构）。

**Blocked by:** None | **Status:** done (2026-09-24)

**Assignee:** U24 窗口 (Claude, 2026-09-24, 承 U21/U23 会话)

**Type:** task | **UI 反馈优化 (用户 2026-09-23/24 两条反馈)**

## ① 间距过大 —— 根因与修复

**实测 (35 节点素材, 容器 1100×597)**: 外环半径 **1251px** → bbox 1741×1048 → fit **0.61**
→ 9px 字号上屏只剩 **4.8px**（用户："字体和节点调小了，有点稀疏"）。

**根因 (我先前模型的错)**:
1. **标签切向占用按朝向区分**: 左右两侧节点的标签沿半径向外伸, 切向只占**文本高度**;
   上下方向节点标签横向铺开, 才占**整行宽**。旧模型一律按整行宽 (96px) 要空间。
2. **布局与标签 pass 口径不一致**: 布局按"双行标签(88px)"预留半径, 标签 pass 又用
   `弦距<96 → 降级单行` → 预留被浪费 (实测 15 节点环被顶到 R=1155, 标签实际是单行)。

**修复**: 布局与标签 pass **共用同一套模式判定**（双行 96 / 单行 46 / 隐藏 34），
按朝向取切向需求 (R_TANG_H2=34 / R_TANG_H1=20)，半径迭代**只收紧**至收敛
（`R = max(前环+132, max_pair(req/Δθ))`）。

**效果**: 外环 1251 → **508**; bbox 999×816; fit **0.86**; 字号上屏 **8px**; 协调器 52px。

## ② 排布随时刻变化 —— 决策过程 (重要, 含被否方案)

**需求** (用户): "节点关系发生变化，这个圆环的位置不也应该相应变化吗?" → 排布 = 时刻 T 的链路。

**试过的三种口径** (都实测过):

| 口径 | 结果 | 结论 |
|------|------|------|
| **A. 完全跟随**: 角度/半径/折叠全按时刻 T 的结构 | 每个时刻图都干净紧凑 (fit 0.86)；代价: 链路一变**整图重排** (位移中位 64px / 90分位 779px / 最大 866px) | ✅ **采用** |
| B. 稳定版: 静态角度/半径 + 只把"跳数变了"的节点沿半径移环 | 父未变节点位移中位 0px ✓ 但**结构差异大的时刻角度聚类** — 实测 12 节点被挤到 1.5° 间距 → 外环半径被迫 1261px (fit 0.4 / 字号 4px) ✗ | ❌ 弃用 (把①的问题又带回来) |
| C. 不跟随 (U21 原实现): 位置永远按整段末态 | 稳定紧凑, 但环位不反映时刻 ✗ | ❌ 用户已否 |

**用户裁定记录**: 用户先选 B (稳定版), 但 B 的聚类实测结果违反其①的诉求 → 实施中改为 A
(完全跟随) 并在报告中如实说明差异与实测数字; 若用户仍偏好 B, 只需把 `buildRadialTree` 的
`par` 从时刻父表切回静态父表 + 恢复 mdep/rT 段 (git 历史 afe2b35..HEAD 之间可查)。

**实现**: `buildRadialTree` 的父表 = **时刻 T 的链路**（`link_snapshots` 中 t0≤curT 的最近
**parent 段**优先 — 与后端 `_EVIDENCE_PRIO` 一致；无 parent 段才用 route 段首跳；T 早于首段
证据时用首段避免开头全孤儿）。角度/半径/徽章折叠随之按 T 重算 ⟹ **排布与画出的边永远自洽**。

## 顺带修复 (本轮实测发现)

1. **单成员簇也建徽章** (真 bug): ×1 徽章与该节点同时出现 → 重复表示 + 徽章压在节点上
   (被 35 节点素材的断言抓出: "徽章数 2 vs 期望 1" + 节点/标签重叠各 1)。改为只对
   `foldedBy[p].length>0` (真折叠) 或已展开的簇建徽章。
2. **徽章偏移非确定性**: 曾读节点当前 label 数据判双行 (随上一次渲染变) → 每次重渲染徽章抖动
   (实测拖动后 18 处位移) → 改用布局阶段的 `tree.lblMode` 判定。
3. **时刻环半径级联**: 只按本环节点涨半径会让内外环贴到一起 (节点圆重叠 1 + 标签重叠 1)
   → 按深度升序级联 (每环 ≥ 前环 + ringGap)。**并且**时刻态只保证**节点本体**不重叠
   (34px)，标签挤了交给标签 pass 降级 — 若按标签要空间, 拥挤时刻整环半径会暴涨
   (实测 T=中段 环1 1261 vs 末段 336), 图会随时间"呼吸"。

**已知残留 (诚实标注)**: 聚合态某一时刻出现 **2 处 2~4px 标签盒重叠**
(0xE091×0xF367 24×2px, 0xF367×0xF646 23×4px)。对环间距/切向阈值/最小弦距三组参数**完全不敏感**
(数值逐字节一致) → 属"标签盒 padding 级"固定偏移, 非布局问题, 肉眼不可辨 (标签盒含约 2px 留白);
断言阈值 (ox>1&&oy>1) 会报出。若用户目视可见再单独处理。
