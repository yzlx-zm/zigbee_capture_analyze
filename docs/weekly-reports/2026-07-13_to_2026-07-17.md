### 周二 / 2026-07-14
**SwitchModule — 项目记忆与架构框架对齐**

### 周三 / 2026-07-15
**z3gateway + SwitchModule — 多项目代码审查**
- 问题：(1) z3gateway 项目的 EZSP 协议通信和安全模块需要与 v4.3.2 版本进行 API 对比审计；(2) SwitchModule 继电器本地控制路径需要完整梳理。
- 方案：逐模块对比 v2024.6.3 与 v4.3.2 的 API 实现，确认接口兼容性；通过全量搜索 relay_action_apply() 调用点，追踪继电器控制的完整调用链。
- 结果：✅ EZSP 全部 10 个模块审计完成，仅 1 处差异（无实际影响）；✅ 继电器控制路径梳理完成（6 个调用点，2 个文件）。

### 周四 / 2026-07-16
**K32 Switch — SPI 时序问题排查**
- 问题：GC9107 模拟 SPI 时钟线上每隔 7 个时钟宽度变宽，硬件人员怀疑是软件起始条件导致。
- 方案：逐行分析 `spi_simulate_send_byte()` 时序，定位到第 62 行在每个字节的第一个 bit 存在冗余 SCK 高电平操作，导致字节边界的时钟展宽。
- 结果：✅ 根因定位完成，明确修复方向。

### 周五 / 2026-07-17
**Zigbee 抓包分析工具 — 新项目启动与 MVP 交付**
- 问题：需要一个本地的 Zigbee 抓包分析工具，支持 pcap 导入、协议解析、拓扑可视化、AI 辅助分析等功能，最终打包为单个 Windows exe。
- 方案：调研参考 Ubiqua 功能清单、MG21 sniffer 固件、SSv5 topology_tools 等已有资源；采用 Python 后端 + 浏览器 HTML 前端架构，pcap → tshark 解析 → JSON → 后端分析 → Canvas 可视化的流水线设计。
- 结果：✅ 完成完整实施计划与架构设计；✅ MVP v2.0 实现（解析器 + 包列表 + 过滤 + 拓扑图 + 时间线 + AI 集成），成功导入 13,656 包测试。

**SwitchModule — SDK Include 分析**
- 问题：需要梳理 SwitchModule 全部 .c/.h 文件的 SDK 头文件依赖关系。
- 方案：扫描 27 个文件（14 .c + 13 .h），按应用层/驱动层/SDK层分类统计 include 依赖。
- 结果：✅ 完成全部 27 个文件的 SDK 依赖分析。
