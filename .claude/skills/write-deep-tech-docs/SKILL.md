# 深度技术文档写作

撰写**原理级**深度技术文档——知识库条目、深度技术文章和学习路径——让小白读者能跟着学到完全理解。仅限用户手动调用。

## 深度标准

此技能要求达到 **L3：原理级**。拒绝 L1 和 L2：

| 级别 | 描述 | 判定 |
|------|------|------|
| L1：API 级 | "调用 `zb_start()` 启动 Zigbee 协议栈。" | ❌ 拒绝 |
| L2：机制级 | "Zigbee 启动：HAL 初始化 → PHY 信道扫描 → MAC 能量检测 → NWK 网络发现。" | ⚠️ 不够 |
| L3：原理级 | "Zigbee 启动的信道扫描使用 IEEE 802.15.4 的 ED（能量检测）扫描。为什么要扫描？2.4GHz ISM 频段是共享频段——WiFi 信道 1/6/11 与 Zigbee 信道 11-26 严重重叠。ED 扫描通过多次采样 RSSI 取平均来判断信道占用。阈值是权衡：太高可能选不到可用信道，太低可能选到被 WiFi 重度占用的信道。算法的噪声基底估计使用多次扫描的滑动中值以滤除瞬态干扰。" | ✅ 目标 |

### "为什么"规则

每个结论必须回答*为什么*：
- "参数 X 设为 3" → ❌
- "参数 X 控制重传超时。设为 3 表示 3 × 16µs = 48µs。这匹配我们在 RF 环境中测得的最坏情况 CSMA-CA 退避时间（47µs）。设得更低会导致在 ACK 到达之前就过早重传。" → ✅

### 来源规则

引用第一手来源，绝不引用二手：
- ✅ "IEEE 802.15.4-2015 §6.2.3 定义 CSMA-CA 算法为..."
- ✅ "EFR32MG21 数据手册 §12.3.4 指定 RSSI 偏移为 -81dBm ±4dB"
- ❌ "根据某博客..."
- ❌ "众所周知..."

## 三种产出形式

### 形式 1：知识库条目（原子单元）

```
用途：精确定义一个概念
篇幅：300-800 字
结构：
  ## <术语>
  定义：（一句话）
  直观理解：（类比或文字图示）
  原理展开：（2-4 段解释机制）
  关联关系：（← 依赖、→ 使能，链接到其他 KB 条目）
  常见误区：（1-3 个"很多人以为 X，其实 Y"的点）
  来源：（规范章节、数据手册页码、参考手册章节）

示例条目：
  - "Zigbee Binding — 直接绑定 vs 间接绑定"
  - "CSMA-CA 退避算法"
  - "BLE 连接间隔与功耗权衡"
  - "IEEE 802.15.4 ACK 超时窗口计算"

保存到：docs/knowledge-base/<简称>.md
```

### 形式 2：深度技术文章（串联叙事）

```
用途：对一个主题的穷尽性处理
篇幅：2000-5000 字
结构：
  ## <标题>
  问题引入：这个主题解决什么问题，为什么存在？
  前置知识：读者应先理解哪些 KB 条目？（带链接列表）
  
  原理拆解（3-6 节）：
    每节：
    - 陈述一个子问题
    - 用原理级深度回答
    - 结尾："此时你应该理解：<检查点>"
  
  设计权衡：为什么选 A 不选 B？如果选 B 会出什么问题？
  实战验证：抓包/逻辑分析仪波形/Wireshark/寄存器 dump 证明它有效
  常见陷阱：3-5 个开发者实际踩过的坑
  延伸阅读：链接到相关 KB 条目 + 深度文章

示例文章：
  - "Zigbee NWK 层路由：协议级全流程讲解"
  - "BLE GATT 从第一原理到数据包分析"
  - "嵌入式低功耗设计：决定电池寿命的 7 个关键决策"

保存到：docs/deep-dives/<简称>.md
```

### 形式 3：学习路径（引导旅程）

```
用途：引导初学者从零到胜任
篇幅：取决于范围；通常 5-10 个阶段
结构：
  ## <标题>
  目标画像：学完这条路径后，你能：<具体能力>
  前置条件：开始前需要知道什么
  
  第 1 阶段：建立心智模型
    → 阅读：KB 条目 A、B、C
    → 实验：<动手练习附预期结果>
    → 检查点："此时你应该能解释..."
  
  第 2 阶段：核心机制
    → 阅读：深度文章 X、KB 条目 D
    → 实验：<更高级的练习>
    → 检查点："..."
  
  [... 阶段 3-N ...]
  
  卡住的地方：读者容易卡住的常见节点及突破方法

示例路径：
  - "从零理解 Zigbee 协议栈"
  - "BLE 应用开发：入门到独立调试"

保存到：docs/learning-paths/<简称>.md
```

## 质量检查清单

最终确认文档前验证：

### 深度检查
- [ ] 每个结论解释*为什么*（不只是*是什么*）
- [ ] 设计权衡被显式陈述（"因为约束 C 而选择 A 而非 B"）
- [ ] 不确定性被标注（"SDK 文档未说明此点；根据行为推断的原因是..."）
- [ ] 第一手来源带着章节/页码被引用

### 小白友好检查
- [ ] 每个术语在第一次出现时给出定义（假设零领域知识）
- [ ] 前置知识被显式列出（读之前需要懂什么）
- [ ] 没有任何步骤跳过了读者需要自行猜测的信息
- [ ] 用文字描述图示，确保不渲染也能理解

### 可验证性检查
- [ ] 提供实验/抓包/代码片段供读者复现
- [ ] 实验步骤完整：环境、工具、步骤、预期结果
- [ ] 如果复现失败，包含排错指导

## 与知识图谱协作

写之前读取：
- `PROJECT-KNOWLEDGE-GRAPH.md`——将主题锚定在工程的实际硬件和协议栈上
- `CONTEXT.md`——确保术语一致，避免与已有词汇表冲突

写 KB 条目时，检查 `CONTEXT.md` 是否已定义该术语。如果没有，提议添加（通过 `/domain-modeling`）。

## 交叉引用

三种形式互相链接：
```
KB 条目 "CSMA-CA" ← 被引用 → 深度文章 "Zigbee NWK 路由"
                               深度文章 "Zigbee MAC 层"
                               学习路径 "从零理解 Zigbee"
```

使用相对 wikilink：`[CSMA-CA](../knowledge-base/csma-ca.md)`，使知识网络在目录移动后仍能存活。
