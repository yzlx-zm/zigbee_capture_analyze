## 0. 抓包可行性（数据现实层）— 部分确认

| 条件 | 要求 | 说明 |
|------|------|------|
| **poll 帧可见性** | ✅ MAC Data Request (cmd 4) 提取（L2-1 同源） | SED 失联的信号源（poll 停止） |
| **LS 邻居表可见性** | ✅ Link Status 邻居表（L3-9 同源） | 路由器失联的信号源（邻居条目消失） |
| **失联的官方确认** | ❌ **无** — 官方明确失联无通知 | 检测器只能报"失联候选"，需现场确认 |

| **大网络稀疏覆盖** | ⚠️ 邻居表条目消失 ≠ 失联 — 表容量替换/设备移动（官方：表满覆盖条目） | test2 误报教训：需全局沉默守卫 |

## 1. 场景识别（入口）

**用户描述关键词**：`设备失联`、`设备消失了`、`网关看设备离线但没收到离开`、`设备不再上报`、`静默`

**典型症状**：
- 设备之前规律通信（poll/上报），突然完全沉默（无 Leave 广播 — 主动离开由 L1-4 覆盖）
- 网关/APP 显示设备离线，但抓包无 Leave/Rejoin
- 其他路由器不再报告该设备（LS 邻居条目消失）
- 父节点超时删除子表（Poll Timeout）后设备需 rejoin 才能恢复

**与相邻场景的区分**：
- 伴随 Leave 帧 → 主动离开/被踢（**L1-4**），非静默失联（交叉标注）
- 伴随 Rejoin → 设备自己发现失联在重入（L2-3 Orphan 循环）
- 下行失败（0x0B）→ **L3-5** 路由层，设备可能仍在线
- 邻居条目消失但设备仍在别处活跃 → 链路变化/移动（非 L2-6，test2 教训）

---

## 2. 正常抓包基线 — ✅ 官方流程确认

```
SED 正常: 规律 poll (LONG_POLL 默认 300s 内) — 父节点每次成功 poll 重置 Poll Timeout
路由器正常: 每 15-16s 发 LS, 邻居表条目维持 (双向 in/out cost 非 0)
邻居 aging: 收到邻居 LS 重置 age (16s 周期), age>6 (~64s) stale → out cost 归 0
```

**正常交互的抓包特征**: poll 间隔稳定（素材实证：中继素材 0x838D poll 中位 0.2s = fast poll / 0x737d 1.0s）；LS 邻居条目持续出现。

## 3. 异常表现 — [官方确认；素材正例待补]

| 表现 | 官方依据 | 素材实证 |
|------|---------|---------|
| 规律 poll 突然停止（≥3× 中位间隔） | 父节点 Poll Timeout 超时删除子表 → 失联 | 中继素材 0x838D（poll 80 次/0.2s 后沉默 89s + Leave）/ 0x737d / 0xd259 — 候选，需现场确认 |

## 4. 判定条件（可编程规则）— 规则框架确认（MCP 核对 2026-08-11）

```
R1 SED 失联候选 (中置信):
    设备 poll ≥3 次 且 poll 间隔中位 ≤60s (规律活跃)
    且 最后 poll 到抓包结束 ≥max(3×中位间隔, 60s) (沉默窗口)
    → 失联候选 (父节点视角: Poll Timeout 未响应)
    ⚠️ poll <3 次 / 非规律 (中位 >60s) → 不判 (长轮询设备沉默是常态)

R2 路由器失联候选 (中置信):
    邻居 B 在 A 的 LS 中曾出现 ≥2 次
    且 A 连续 ≥3 条 LS 无 B (条目消失)
    且 B 全局沉默 (B 在 A 最后报告后无任何帧 — 排除表替换/移动)
    → 失联候选 (邻居表 stale)
    ⚠️ 大网络稀疏覆盖: 条目消失但设备活跃 = 链路变化, 非失联 (test2 教训)

交叉: 命中设备伴随 Leave → 主动离开/被踢 (归 L1-4)
边缘标注: 沉默/消失延伸到抓包末尾 → "无法区分失联与抓包结束" (诚实)
```

**判定参数**（待素材校准）:
- R1: poll ≥3 / 中位 ≤60s / 沉默 ≥3×中位且 ≥60s
- R2: 出现 ≥2 / 消失 ≥3 条连续
- ⚠️ 阈值需正例素材校准（第 14 层）

## 6. 根因链路 — [官方确认]

```
设备静默失联
├─ SED: 掉电/休眠超时 (超过 Poll Timeout 未 poll) → 父节点删子表 → 失联
│   ├─ 电源问题 (电池耗尽/掉电) — 需现场
│   ├─ 固件异常 (poll 停止) — 需现场
│   └─ 父节点 Poll Timeout 配置 < LONG_POLL (配置错误) — 需现场
├─ 路由器: 掉电/故障 → 邻居表 stale (age>6) → 条目消失 (R2 可见)
└─ 链路恶化 → 单向失联 (与 L3-9 非对称交叉)
```

## 8. 自动检测盲区 — [官方确认]

1. **失联无官方通知**（官方明确）— 检测器只能报"候选"，铁证必须现场确认
2. **抓包窗口边缘**：沉默到末尾 ≠ 失联（设备可能在抓包后活跃）
3. **单 sniffer 覆盖**：SED poll 可能漏抓（poll 是 MAC 帧，需含 MAC 帧素材）
4. **邻居表容量替换**：大网络条目消失是常态（官方：表满覆盖 stale/最差条目）
5. **Poll Timeout 配置未知**：R1 阈值（60s）基于"规律活跃"而非 Poll Timeout 配置（配置项无线上协商，官方）

## 11. 上下游关联 — [骨架]

- **L1-4 TC 拒绝/踢人**: 伴随 Leave → 主动离开/被踢（非静默失联）
- **L2-3 Orphan/Rejoin 循环**: 设备自行发现失联 → rejoin
- **L3-9 非对称链路**: stale（邻居停发 LS → out 归 0）与 L2-6 R2 同源；单向链路恶化可致失联
- **L3-5 源路由失效**: 下行断链但设备可能在线（poll 保持）
- **L2-1 频繁离线**: poll 间隔超时（R1 阈值与 L2-1 R1 互补：L2-1 超时仍在 poll / L2-6 poll 停止）

## 12. 判定示例（真实抓包）— ⚠️ 正例待素材（ADR-0002 硬约束）

**负例（已实证，不误报）**: test2 大网络 — 邻居条目消失但设备全局活跃（沉默 0-14s）→ 排除（表替换/移动）；直连泛洪 0x96A8 沉默 147s 但无 poll 基线（非 SED）→ 不判 R1。
**候选（需现场确认）**: 中继素材 — 0x838D（poll 80 次/0.2s 后沉默 89.3s + Leave）/ 0x737d（53 次/1.0s → 130.3s + Leave）/ 0xd259（15 次/1.0s → 82.8s）/ 0x8A41（R2 邻居消失 + 全局沉默）— 全部沉默延伸到抓包末尾，标注边缘不确定。

**待素材**: 抓包窗口内明确失联（设备 poll 停止后抓包继续且无该设备任何帧）+ 现场确认离线。
