# Q&A 需求对齐模式 (qa-align)

## 何时使用

用户说 "进入你问我答" / "Q&A" / "需求对齐" / "对齐颗粒度" 时激活。

适用于：
- 新功能开发前的需求澄清
- UI/可视化方案的颗粒度对齐
- 复杂功能的多方案选择
- 数据准确性有疑问时的核查

## 核心原则

```
探索 → 发现问题 → 结构化提问 → 确认 → 实施 → 回退安全网
```

## 执行流程

### Phase 1: 并行探索 (2-3 agents)

在提问之前，必须全面了解现有代码和数据结构：

```
你: 启动 2-3 个 Explore Agent, 并行搜索:
  - Agent 1: 相关后端代码、API 端点、数据结构
  - Agent 2: 前端渲染逻辑、交互模式、现有组件
  - Agent 3: 原始数据源 (tshark fields / pcap 帧 / 协议字段)
```

**原则**: 不问已知信息的问题，不问代码里已经写死了的东西。

### Phase 2: 结构化提问

使用 `AskUserQuestion` 工具，每次 1-4 个问题：

**问题设计规则**:
1. **一问一维** — 每个问题只关注一个决策维度
2. **给出推荐** — 第一个选项标记 "(推荐)"，给出理由
3. **图文预览** — 复杂选项用 ASCII mockup 做 preview
4. **多选 vs 单选** — 互斥用 single，并行用 multiSelect

**示例**:
```json
{
  "header": "可视化方案",
  "multiSelect": true,
  "options": [
    {"label": "A) 力导向图 (推荐)", "description": "Cytoscape力导向布局...", "preview": "ASCII图"},
    {"label": "B) 层级树", "description": "...", "preview": "..."}
  ]
}
```

### Phase 3: 确认 + 计划

- 汇总所有回答，用表格确认
- 遇到不明确的回答 → 再问一轮
- 进入 `EnterPlanMode` → 写计划 → `ExitPlanMode` 等审批

### Phase 4: 实施

- 审批通过后开始编码
- 每完成一个 Step 立即确认
- 改动大时频繁 git commit（回退安全网）

### Phase 5: 数据核查（关键！）

这是本次对话最重要的调试技巧：

```
永远不要完全信任你第一次提取的数据。
工具可能有 bug (如 tshark JSON 多实例字段只保留最后一个)。
必须用原始数据源交叉验证。
```

**核查流程**:
1. 用原始工具直接查询（如 `tshark -T fields`）对比 API 返回
2. 抽样几帧检查字段完整性
3. 发现差异 → 追踪根因 → 修复 → 重新验证

## 安全实验模式

这是"大胆尝试"能成立的基础：

```bash
# 每次改动前保证可回退
git commit -m "working state"

# 尝试新方案...
# 如果崩了:
git reset --hard HEAD~1

# 然后重新来过
```

**原则**:
- 大胆试方案，反正 git 能回退
- 每次 commit 保持小粒度，方便精确回退
- 试错是正常的，用户说"越做越错"时立刻回退，不要将错就错

## 本次对话的调试技巧总结

### 1. 双通道数据验证（最关键）

```
tshark -T json    → 结构化但可能缺字段 (多实例只保留最后一个!)
tshark -T fields  → 完整但需手动解析
→ 两者结合, JSON 为主, fields 补充缺失字段
```

### 2. 边分离去重

流量边和路由边各用各的去重集合，避免互相覆盖：
```
trafficSeen ≠ routeSeen
```

### 3. 高亮逻辑核验

高亮节点时应包含完整路径（所有跳），不能只高亮 1-hop 邻居：
```
0x02C2 高亮 → 应包含 0x9F1B, 0x0000 + 整条路径边
不是: 仅高亮 0x02C2→0x9F1B, 后面淡出到 4%
```

### 4. 路由变更检测

同一设备的多条路径不应该是 bug，可能是路由变更：
- 保留所有路径
- 加时间戳区分当前/历史
- 这本身就是一个重要分析指标

### 5. 动态样式陷阱

Cytoscape 的 `edge[path_idx=0]` 动态选择器可能崩溃。
用静态 class 选择器 `edge.path-c0` 更安全。

## 不是 "grillme"

目前没有叫 "grillme" 的 Claude Code skill。但 Q&A 模式下用 `AskUserQuestion` + preview 卡片的效果，本质上就是"结构化需求访谈"——比单纯的文字对话高效得多。

推荐配合使用的内置能力：
- `/plan` → EnterPlanMode（复杂任务先写计划）
- `AskUserQuestion` + `preview` 字段（关键！让用户看图选择）
- `git reset --hard`（大胆试的安全网）
- `TodoWrite`（跟踪进度，防止遗漏）
