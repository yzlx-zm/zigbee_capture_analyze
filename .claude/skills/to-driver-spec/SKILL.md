# 生成驱动规范

将当前对话上下文（通常是 `/grill-embedded-design` 会话的输出）综合为驱动设计规范。**不要**重新采访用户——只使用已经讨论过的内容。

读取 `PROJECT-KNOWLEDGE-GRAPH.md` 和 `CONTEXT.md` 获取领域词汇和工程上下文。

## 流程

1. 回顾对话中在问答期间做出的所有设计决策
2. 将决策映射到下面的规范模板
3. 确定测试接缝
4. 将规范发布到工程中

## 规范模板

```markdown
# 驱动规范：<驱动名称>

## 概述
- **驱动名称**：<名称>
- **目标硬件**：<MCU / SoC>
- **内核版本 / RTOS**：<版本>
- **在架构中的位置**：（引用 PROJECT-KNOWLEDGE-GRAPH.md 模块图）

## 硬件接口
- **外设基地址**：<地址>
- **寄存器映射**：（仅关键寄存器——完整映射引用数据手册 §X）
- **引脚分配**：| 引脚 | 功能 | 复用/配置 | 备注 |
- **时钟源**：<源> @ <频率>
- **复位域**：<域>
- **电源域**：<域>
- **数据手册引用**：<章节号和页码列表>

## 软件接口

### 用户空间 / 应用接口
| 接口 | 路径/命令 | 方向 | 语义 |
|------|----------|------|------|
| ioctl | CMD_XXX | IOW | ... |
| sysfs | /sys/.../attr | RW | ... |
| read/write | /dev/xxx | data | ... |
| mmap | /dev/xxx | 零拷贝 | ... |
| poll | /dev/xxx | event | ... |

### 内核 / 内部接口
（内核驱动：子系统期望什么？）
（RTOS：任务/队列接口长什么样？）

## 内部设计
- **模块分层**：（core → hal → platform）
- **状态机**：（状态、转换、触发条件）
- **数据流**：（DMA 缓冲区管理、队列深度、零拷贝路径）
- **并发模型**：（锁层级、ISR/任务分工、下半部机制）

## 电源管理
- **支持的电源状态**：（列表）
- **唤醒源**：（列表，带延迟估计）
- **状态保存/恢复**：（哪些寄存器必须保存，哪些会保留）

## 错误处理
- **错误分类**：（可恢复 / 需复位 / 致命的）
- **每类的恢复策略**
- **上报路径**：（内核日志 / ftrace / 回调 / 用户空间通知）

## 测试策略
- **测试层级**：（单元 / 集成 / HIL / 手动）
- **接缝位置**：测试挂载位置
- **模拟策略**：无硬件时如何测试
- **覆盖目标**：必须测试的内容

## 不包含的范围
- （显式排除的功能及原因）

## 补充说明
```

## 发布

保存到工程的 `.scratch/<功能简称>/spec.md` 下。优先本地文件——更快，且保持规范与代码相邻。
