## H — 密钥同步扩展 (解密率关键项)

### 现状与缺口 (总控已查)
- `_sync_ubiqua_keys` (files.py:252) **只同步 Network Key** (`client.get_network_keys()` →
  `key_store.merge_from_ubiqua`), 且**静默** (成功/失败用户无感)
- **实际解密瓶颈是设备 Link Key**: 项目实证 (P4) 中继包 99.98% 安全帧为 key_type=0
  (设备唯一 TC link key), 58.5% 帧解密失败 = 缺 link key **非 bug**
- Ubiqua 的 `Keys` 表通常同时存 Network Key 与 Link Key; `ubiqua_api.list_keys()` 可读全部

### 决策
- 同步范围: **全部 key 类型** (Network + Link), 按 hex 去重合并 (沿用 key_store 机制)
- 时机: 导入前自动 (现行为) + 提供**手动"刷新密钥"入口**
- **可见性**: 同步结果展示 (如 `从 Ubiqua 同步 +3 个密钥 (1 Network / 2 Link) · 总 306`)
- 未连接 Ubiqua → 静默跳过 (不阻断导入), 但手动入口提示"Ubiqua 未运行"

### 验证
- 同步后解密率提升可量化 (同素材前后对比, 记录实际数字)
- key 类型分类正确 (Network/Link 分别计数)
- 回归: 无 Ubiqua 时行为不变

## I — 导入时按 PAN 过滤 (数据纯净度)

### 现状与缺口
- 预扫 (`cubx_splitter.prescan_cubx`) 返回 total_frames/ts_first/ts_last/duration/histogram/
  channels/lqi/rssi — **无 PAN 分布**
- 多网络混杂包常见 (中继/群控包); U13 曾因多 PAN 混杂出过 bug → 数据纯净有价值

### 决策
- 预扫增加 **PAN 分布统计** — 实现方式: 轻量扫描 (只读 Raw 前几字节取 MAC FCF+PAN,
  **不做完整协议解析**, 保持秒级)
- 预扫面板列出 `PAN 0x580C: 2174 帧 / PAN 0x1234: 890 帧 …` → 用户选择目标 PAN
- 导入/拆分时只保留选中 PAN 的帧 (未选 = 全量, 保持现行为)
- 多 PAN 时默认建议选择帧数最多的 (不自动应用, 需用户确认)

### 验证
- PAN 分布与解析后实际统计对账一致 (同一素材)
- 选 PAN 后导入: 帧数 = 该 PAN 帧数; 未选 = 全量 (回归)
- 单 PAN 素材: 面板不显示选择器 (无干扰)

## J — 一次拆多段 (批量拆子包)

### 现状
- 拆分面板一次拆一个窗口 (U18 加了 ◀▶ 分段推进, 但仍是逐段)

### 决策
- 面板加"按段长批量拆": 输入段长 (分钟) + 范围 (当前窗口) → 一次拆出 N 个子包
- 结果进现有子包清单 (N 条, 下载/导入按钮不变)
- 边界: 末段不足一段长 → 按实际截断 (或丢弃, 实现时定, 需提示);
  段数上限保护 (如 ≤20 段, 防误操作产生海量文件) + 超额提示
- 性能: 优先**单次扫描拆多段** (若现有 `split_cubx` 是单窗, 评估是否需要扩展为多窗一次扫描;
  简单实现=循环调用时, 如实记录耗时)

### 验证
- 60 分钟素材拆 5 分钟段 → 12 个子包, 帧数总和 = 源窗帧数 (无重叠无遗漏)
- 子包清单 N 条, 下载/导入可用
- 段数上限与越界提示正常
