## 模式 1：DA13 网络 — 下行源路由失败 (0x0B)

**规律**（7 个故障包一致）：
- 0x0B **全由同一中继发出**（入网失败系列 = 0x703E；网关修改系列 = 0x87AB）
- 0x0B 起始距设备 Announce **2.4~5.0s**——设备刚入网后立即开始下行失败
- target = 刚入网的那台设备（每包一台）
- 时长两态：网关修改系列短促（3-6 轮/3-5s）；入网失败系列持续（8-12 轮/40-67s）
- **入网成功 ≠ 下行转发正常**：标注"网关修改-入网成功"的包依然带 0x0B

**与 838D 案例同构**：0x1885→0x838D（Confirm 经中继转发失败）——DA13 网络的 0x703E/0x87AB 对刚入网设备的下行失败是同一机制（L3-5-R1）。

**健康对照**（DA13-2 / 艺山网关修改 = 0 NS）→ 特定配置下完全干净，问题与中继配置/网关配置组合相关。

## 模式 2：G32 网络 — 上行 MTORR 失败 (0x0C) + 间接超时 (0x06)

**G32_0626**（用户提供，运营期 36 分钟抓包，无入网活动）：
- **0x0C ×216**（39 轮/29 分钟），src 全 = 0xBE5A（中继），target 分布 0xBE5A×100 / 0xEE48×86 / 0x0000×30
- **0x06 ×38**（间接传输超时），src 全 = 0xBE5A → 0xEE48（发往睡眠设备的消息过期）
- 0xBE5A 是活跃中继：Route Record 经它转发 ×48（总 138）、Link Status ×109（邻居仅 0x0000, cost 1/1）
- **持续失败**：0x0C 39 轮跨 29 分钟——非瞬态

**解读**：0xBE5A 上行 MTORR 路径持续失败（转发设备→网关的数据失败）+ 对 0xEE48 的间接消息过期。
矛盾点：Link Status 显示与协调器直连 (cost 1/1) 却上行失败——断链可能在更高层（源路由表/MTORR 表与射频不符），
或 0xBE5A 转发的是子设备的上行（子设备链路问题经它显现）。

## 根因方向（供现场/网关侧排查）

1. **DA13 下行模式**：中继对刚入网设备的下行源路由失败 — 查中继的源路由表更新时机、网关修改的配置项
   （"网关修改"系列 v1→v3 仍在报错 → 修改项未覆盖下行问题；艺山网关=健康 → 配置组合差异）
2. **G32 上行模式**：中继 0xBE5A 上行 MTORR 持续失败 + 间接超时 — 查该中继的上行链路/邻居表/
   子设备 poll 行为（0xEE48 的间接消息为何过期）
3. **健康对照启示**：同一网关（DA13）不同配置干净 vs 报错 → 配置可复现性，建议对比
   "艺山网关修改"与"网关修改 v1-v3"的差异点
