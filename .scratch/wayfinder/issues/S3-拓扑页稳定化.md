## 第二轮: 拓扑绘制原理重构 (2026-08-27 用户逐项对齐)

**用户反馈**: "问题多多…目前功能不是很满意…重新梳理一下我们画图的原理和内容是否足够精确"
**对齐决策 (用户确认, 不可更改)**: ①以上行链路为准构建拓扑 ②Link Status 邻居关系**不上拓扑图**
③链路证据 = 30s 窗内硬核证据 (poll 父 / RR / 网关下行控制路径), 窗内无 → **顺延前 30s**
④时间线上出现过的节点, 有明确在线证据 (终端 poll / 路由任意帧) 持续渲染不消失
⑤下行路径仅作证据参与父子判定, 不上图 ⑥默认视图 = 全貌 (每节点最近证据),
拖动时刻游标 = 30s 证据窗时刻视图 ⑦链路历史面板保留, 分段阈值 60s→30s

### 实施 (后端 backend/api/topology.py + 前端 topo.js)

1. **节点全量 + online 协议判定**: events 节点集 = 全量事件节点 ∪ 链路证据节点
   (poll/assoc/源路由参与), 时间窗切换节点不消失; `_online_map` 协议判定
   (终端须窗内 poll / 路由任意帧 / 无时间窗全在线); **修复 bug**: 窗内无帧节点
   曾默认 online=True (前 4s 窗 78 全在线实锤) → 有时间窗默认 False
2. **四来源链路证据 `_link_evidence_parent`**: poll > assoc > rr > **down**
   (源路由帧 nwk_relays, chain=[src]+relays+[dst] 每节点父=前一个);
   证据窗 = [t0-30s, t1] (顺延前 30s); 协调器无父守卫
3. **`_all_link_segments`**: max_gap 60→30s + assoc/down 证据 + 段带 evidence 字段
4. **前端**: 邻居边全移除 (按钮/渲染/CSS/tooltip/图例); online=false → inactive 灰显;
   snapAt 时刻模式 (curT-段末>60s 证据过旧) vs 全貌模式 (最近证据) — slideMode 标志
   (拖动游标进入时刻模式, 重置/退出聚焦恢复全貌); 链路历史面板证据标注
5. **过程中修复 (中继包 78 节点实测暴露)**: runLayout 引用 renderGraph 局部变量
   `nbt` → ReferenceError (4688 小包 offAll 空未触发) — 改模块级 topoNbt
