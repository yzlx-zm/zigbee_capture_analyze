## cubx schema 实证 (总控已查, sqlite_master 全表)

```
Addresses(Id, Long TEXT, Short TEXT)   Keys(Id, Key BLOB, Type TEXT)
Metadata(Key TEXT PK, Value TEXT)      Nodes(Id, X REAL, Y REAL, Label TEXT)
Packets(Id PK AUTOINCREMENT, Raw BLOB, Stack INT, Channel INT, Timestamp REAL,
        TimeDelta REAL, LQI INT, RSSI INT, Comment TEXT)
sqlite_sequence
```
→ 拆文件 = 建同 schema 新库 + 原样复制 Addresses/Keys/Metadata/Nodes +
Packets 选窗 rows (保原 Id + sqlite_sequence 同步, Ubiqua 兼容最稳)

## 实现要点 (总控设计)

### 1. 新文件 backend/cubx_splitter.py
- `prescan_cubx(path) -> dict`: 只读 sqlite 元数据 (不解析 Raw):
  - total_frames / ts_first / ts_last / duration_s
  - 帧密度直方图 (等宽 ~60 桶: {ts_start, count})
  - channel 分布 + lqi/rssi 概要 (avg/min/max)
  - 秒级返回 (14.9 万行 Timestamp 流式读)
- `split_cubx(src, ts_start, ts_end, out_path, progress_cb=None) -> dict`:
  - 读原库 schema (sqlite_master CREATE TABLE) → 新库建同 schema
  - 全量复制 Addresses/Keys/Metadata/Nodes
  - Packets 选 Timestamp ∈ [ts_start, ts_end] rows, **保原 Id** + sqlite_sequence 同步
  - progress_cb 按 rows 扫描进度上报
  - 返回 {in_frames, out_frames, out_path}
- 产物命名: `<原名>_<YYYYMMDD_HHMMSS>-<YYYYMMDD_HHMMSS>.cubx`, 与原文件同目录

### 2. API — backend/api/files.py
- `POST /api/cubx/prescan` (path) → 预扫结果 (同步返回, 秒级)
- `POST /api/cubx/split` (path, ts_start, ts_end) → 后台任务 (复用 _start_import
  基建, 任务表共用, stage 区分"拆分" vs "导入"); done 后前端自动
  POST /import/local-cubx 导入拆分产物 (拆产物 <30MB 走现有直接导入, 不递归拆分)

### 3. 前端 — frontend/js/import.js
- 本地 cubx 导入: 文件 >30MB → 弹预扫面板 (帧密度直方图 + 总帧数/时长/channel 概览)
  → 双滑块选窗 → [拆分并导入] → 拆分进度 (顶栏三态) → done 自动发起导入 → 现有导入进度
- 小文件直接导入 (现有行为不变); 任何 cubx 有手动"拆分导入"入口
- 直方图: 轻量 div/canvas 柱状图 (~60 桶), 无需图表库
- app.js/index.html 版本号递增 (v=YYYYMMDD 惯例)

### 4. 附带必修 — backend/cubx_reader.py
- `_parse_rows_parallel` 加 progress_cb: 并行分支无进度上报是进度条卡死根因。
  修法: 分块提交 (executor.submit + as_completed 按块计数) 或 map(chunksize)
  后按完成块上报; 粒度按块不必逐帧
- `_run_cubx_local`/`_run_cubx_import` 的 _cb 因此在大包也持续上报
