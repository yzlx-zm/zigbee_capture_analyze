## ⚠️ 结论修正 (2026-08-10, 用户质疑"只解析5%" → 自审发现收益估算错误)

**错误**: 原报告称 "只解析 5% 帧 → 20x 提速"。基于 29MB 素材帧数分布 (Data 5%)
假设"跳过 95% 帧 = 省 95% 时间"。

**实测推翻** (按帧类型解析成本实测, 抽样 2000 帧/类):
| frame_type | 解析速度 | 单帧成本 | 全量 67 万帧成本 |
|-----------|---------|---------|-----------------|
| 1 Data | 555 包/s | **1.80 ms** | **63s (60%)** |
| 3 Cmd | 9,493 包/s | 0.11 ms | 31s |
| 2 Ack | 25,602 包/s | 0.04 ms | 13s (12%) |
| 0 Beacon | 5,201 包/s | 0.19 ms | 1s |

→ 成本主体 = **Data 帧 (60%)**, 而预筛保留全部 Data 帧; Ack 帧解析本身极便宜
(0.04ms), 跳过它对总时间影响小。

**修正后收益** (29MB 素材, 混合估算 107s ≈ 实测 105s 校准):
- 预筛 include_mac_frames=True (UI 实际路径): 解析 49.4% 帧 → ~94s (**1.1x**)
- 预筛 include_mac_frames=False (非 UI 路径): 解析 5.2% 帧 → ~63s (**1.7x**)
- 多进程并行 (Data 帧 8000 样本实测): 2 进程 1.55x / 4 进程 **2.31x**
- 组合 (预筛 True + 并行 4): ~2.5x — 249MB ~14min → ~5.5min

**结论**: 帧数预筛单独收益有限 (UI 路径 1.1x); Data 帧 NWK 解析/解密 (1.8ms/帧)
才是真正瓶颈。可行的真实优化: ① 预筛 (精准零风险, 收益小) ② 多进程并行
(~2.3x, 需处理 spawn/pickle/keys/进度回调语义) ③ 手写 bytes 解析替换 scapy
(Data 帧或快 ~6x, 但需与 scapy 逐位一致 — 违背"精准优先", 不建议)。
方案选择待用户决定 (原 20x 承诺撤回, 诚实标注)。

## Resolution (2026-08-10, 用户批准组合方案: 预筛 + 并行)

**实施** (backend/cubx_reader.py):
- `_cubx_prefilter(raw, include_mac_frames)`: bytes 级预筛 (不构造 scapy, 读
  raw[0]&0x07): Data→保留; Beacon/Cmd→仅 include_mac_frames 时保留;
  Ack/reserved(4-7)→排除; raw<3→保守保留 (超集安全)
- 多进程并行: `_parse_rows_parallel` — ProcessPoolExecutor (2-4 workers,
  initializer 注入 keys, KeyRecord 可 pickle 验证), chunksize=1000;
  **失败自动回退串行** (行为与旧版一致); 候选帧 <8000 走串行 (进程开销不值)
- 主循环: 预筛 → 候选解析 (并行/串行) → 原过滤逻辑不变 → 进度回调语义不变
  (idx 基于全量行数)

**双向一致性验证** (.scratch/verification/p3_consistency.py — 入库回归工具):
新旧路径指纹 (packet_id/类型/关键字段) 逐位对比, **8/8 素材全部一致**:
中继入网/群控压测/test2/标准入网/29MB 全量/69MB/112MB/249MB (大包子集 5 万帧
双向 + 新路径全量)

**实测提速** (新路径 vs 旧路径):
| 素材 | 物理帧 | 旧 | 新 | 提速 |
|------|--------|-----|-----|------|
| 群控压测 | 108k | 36.7s | 13.5s | 2.72x |
| test2 | 13.5k | 78.0s | 29.0s | 2.69x |
| 29MB | 670k | 93.1s | 30.2s | 3.09x |
| 249MB | 2,880k | ~14min (外推) | **234s** | ~3.6x |
| 标准入网 (887 帧) | — | 3.7s | 3.8s | 0.98x (小包无收益, 符合预期) |

**回归**: p1_regression 15/15 PASS; test_parser_verify 9/3 与基线持平
(既有失败, 非本次引入)。

**与修正后预估对比**: 预估 ~2.5x, 实测 2.7-3.6x — 预筛 + 并行叠加效果优于
单独并行 (预筛让并行只处理成本帧, IPC 传输量下降)。
