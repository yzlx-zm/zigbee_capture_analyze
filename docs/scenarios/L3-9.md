## 1. 场景识别（入口）

**用户描述关键词**：`上行通下行断`、`单向能控制`、`设备能上报但控制不了`、`链路不稳定`、`方向性失败`

**典型症状**：
- 命令下行失败（设备收不到）但设备上行上报正常 — **方向性失败**
- 同一对节点 LS 双向 cost 严重不对称（in=1 / out=7）
- 路由选择绕远路（路由表路径成本异常）
- 下行重传风暴 + 上行畅通（与 L3-1/L3-5 症状重叠）

**与相邻场景的区分**（详见第 7 层）:
- 伴随 Network Status 0x0B（下行源路由失败）→ **L3-5** 为主，L3-9 为候选根因（非对称链路可导致方向性路由失败）
- 伴随 0x0C（上行 MTORR 失败）→ L3-5 R2，同理 L3-9 候选
- 无方向性差异，仅单帧无 ack → 链路瞬态 / 抓包盲区

## 2. 正常抓包基线 — ✅ 官方流程确认

**LS 机制**（官方）:
```
路由器每 15-16s (±1-2s jitter) 发一次 Link Status（1-hop 广播，无重试，NWK 命令帧 cmd=8）
├─ 载荷：非 stale 邻居列表 + 每个邻居的 in_cost / out_cost
├─ in_cost：本地 PHY LQI 加权平均 → 查表 (1-7, 1=好 7=差)
├─ out_cost：邻居最近一次 LS 中报告的"我"的 in_cost (0-7, 0=未知)
│   └─ out=0 条件（官方）：邻居 LS 未在最近 16s 内收到 / 我的 ID 不在其最近 LS 中 / 2-3 次交换前
└─ 双向报告（A 报 B 的 in_cost == B 视角的 B→A 接收质量）→ 一对节点的双向成本
```

**正常交互的抓包特征**: 健康链路的双向报告对称（G32 素材 BE5A↔协调器 in=1/out=1 全程 187 条/40min 实证）；out=0 仅出现在初期（2-3 次交换内）或 stale 后。

## 4. 判定条件（可编程规则）— 规则框架确认（MCP 核对 2026-08-10）

```
R1 双向成本不对称 (中置信, 字段级):
    同一对节点 (A,B) 双向 LS 报告 in_cost 差 ≥3 (A报B的in_cost vs B报A的in_cost)
    且双方各自报告 ≥2 次 (排除单次交换噪声)
    → 命中"非对称链路候选"

R2 持续 one-way (中置信, 字段级):
    (A,B) 报告 ≥3 次且 **全程** out_cost=0 (非初期/非瞬态)
    → 命中"one-way 链路候选"
    ⚠️ out_cost 方向语义: (A,B) 的 out_cost = B 报告的 A 的 in_cost (B 收 A 的质量);
       out=0 持续 = B 未在最近 LS 中列出 A = **A→B 方向接收缺失** (one-way)
    ⚠️ 前提 1: 目标邻居 B 自己必须发过 LS (路由器) — 终端不参与 LS, out=0 是正常态
    ⚠️ 前提 2 (2026-08-10 修正): **双向数据可见** — (B,A) 报告存在 (B 的 LS 被抓到且列出 A);
       大网络/单抓包器稀疏覆盖下 out=0 是 LS 交换不足的常态 (test2 素材 68% out=0 误报教训)
    ⚠️ 前提 3 (2026-08-10 修正): **全程 out=0** — 前段有值后归 0 = stale 重置
       (官方: age>6 时 outgoing cost 重置为 0) = 邻居停止发 LS (静默/离线, 归 L2-6), 非 one-way

R3 方向性失败交叉 (提示级, 与 L3-5 交叉):
    L3-5 命中方向性失败 (下行 0x0B / 上行 0x0C) 且同链路存在 R1/R2 候选
    → 根因候选: 非对称链路 (需现场确认; 单凭方向性失败不判 L3-9)
    ⚠️ R3 单独命中 (无 R1/R2) 不触发 L3-9_HIT — 只追加提示

判定收敛: 设备级输出 (R1/R2 命中 ≥1 条链路)
```

**判定参数**（待素材校准）:
- R1 cost 差阈值 ≥3（cost 1-7 的显著差；官方示例 95% vs 15% 质量差对应 cost 差大）
- R1 时间对齐: 双方最新报告时间差 >60s 跳过（LS 周期 15-16s，60s≈4 次交换 — 自审修正 2026-08-10）
- R2 报告 ≥3 次 + 尾部 50% out=0（持续判定）
- ⚠️ 短抓包 (<45s) 或单侧报告缺失 → 不可判定（第 0 层）

## 6. 根因链路 — [官方确认]

```
方向性失败 / 路由不稳定
└─ 非对称链路 (A→B 好, B→A 差)
   ├─ 发射功率差异 (制造差异, 官方)
   ├─ 接收灵敏度差异 (官方)
   ├─ 元件差异/天线 (官方)
   └─ 本地噪声底差异 (官方)
      ↓ 路由发现用单向成本建反向路由 (官方: 假设对称的缺陷)
      → 反向路由质量差 → 方向性投递失败 (838D 案例疑似形态, 待现场确认)
```

## 7. 混淆项（长得像但不是）— [骨架]

| 混淆项 | 区分 |
|--------|------|
| out=0 初期（<3 次交换） | 官方：2-3 次交换才有成本估计 — 短抓包/初期 out=0 正常，不判 one-way |
| out=0 单帧 | 可能该次 LS 恰未列出我 — 需持续性（≥3 次报告 + 尾部 50%） |
| L3-5 源路由失效（0x0B） | 断链本身是结果，非对称是候选根因之一 — R3 只做交叉提示 |
| 抓包漏 LS（sniffer 位置） | LS 1-hop 广播，单侧报告缺失 = 不可判定（第 0 层），不得推断为 one-way |
| 目标设备非路由器（不发 LS） | SED/终端不发 LS（官方：仅路由器）— 无 LS 条目 ≠ 非对称 |
| **stale 重置（邻居停发 LS）** | 前段 out>0 后归 0（官方：age>6 重置）— 设备静默/离线信号（归 L2-6），非 one-way（test2 素材 5 条实证） |
| **大网络稀疏覆盖** | 单抓包器只见部分 LS，out=0 是交换不足常态（test2 素材 68% out=0）— 需双向可见守卫 |

## 8. 自动检测盲区 — [官方确认]

1. **单 sniffer 只见部分 LS**：LS 是 1-hop 广播 — 双向条目都抓到才能判 in/out 差；单侧缺失 → 不可判定
2. **out=0 语义多重**：初期未交换 / stale 老化（16s）/ 对方未列出我 — 需时间序列区分
3. **非对称的根因不可见**：发射功率/灵敏度差异是设备侧属性，抓包不可直接测 — 检测器只能报"非对称候选"，根因需现场/设备信息
4. **SED 不参与 LS**：涉及终端设备的链路非对称无 LS 数据，只能靠行为级（方向性失败）

- **L3-5 源路由/MTORR 失效**: 方向性失败的主判定（0x0B/0x0C）；L3-9 是候选根因（R3 交叉）
