# Q&A 需求对齐模式 (qa-align)

## 何时使用

用户说 "进入你问我答" / "Q&A" / "需求对齐" / "对齐颗粒度" 时激活。

适用于：
- 新功能开发前的需求澄清
- UI/可视化方案的颗粒度对齐
- 复杂功能的多方案选择
- 数据准确性有疑问时的核查

## 核心原则

```
探索 → 发现问题 → 结构化提问 → 确认 → 实施 → 回退安全网
```

## 执行流程

### Phase 1: 并行探索 (2-3 agents)

在提问之前，必须全面了解现有代码和数据结构：

**原则**: 不问已知信息的问题，不问代码里已经写死了的东西。

### Phase 2: 结构化提问

使用 `AskUserQuestion` 工具，每次 1-4 个问题：

**问题设计规则**:
1. **一问一维** — 每个问题只关注一个决策维度
2. **给出推荐** — 第一个选项标记 "(推荐)"，给出理由
3. **图文预览** — 复杂选项用 ASCII mockup 做 preview
4. **多选 vs 单选** — 互斥用 single，并行用 multiSelect

### Phase 3: 确认 + 计划

- 汇总所有回答，用表格确认
- 遇到不明确的回答 → 再问一轮
- 进入 `EnterPlanMode` → 写计划 → `ExitPlanMode` 等审批

### Phase 4: 实施

- 审批通过后开始编码
- 每完成一个 Step 立即确认
- 改动大时频繁 git commit（回退安全网）

### Phase 5: 数据核查

永远不要完全信任你第一次提取的数据。必须用原始数据源交叉验证。

## 安全实验模式

```bash
git commit -m "working state"
# 尝试新方案...
# 如果崩了:
git reset --hard HEAD~1
```

## 调试技巧

1. **双通道数据验证**: tshark -T json + -T fields 互补验证
2. **边分离去重**: 不同类型边用各自去重集合
3. **高亮全路径**: 节点高亮包含完整路径所有跳
4. **路由变更检测**: 同设备多条路径可能是历史变更，保留并标注时间
5. **静态 class**: 避免动态 CSS 选择器（Cytoscape）
