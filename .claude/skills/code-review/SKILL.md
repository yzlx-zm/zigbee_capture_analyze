# 代码审查

对代码进行双轴审查——**规范轴**（编码约定 + 坏味基线）和**需求轴**（代码是否匹配规范/需求）。

## 流程

1. 确定 diff 基准点
2. 确定需求来源（规范文档 / 数据手册 / .scratch/ 下的 spec）
3. 按规范轴和需求轴分别审查
4. 汇总两份报告

## 基线检查项

审查时关注：正确性（死代码、逻辑错误）、健壮性（错误处理、超时）、可维护性（魔法数字、耦合泄漏）。

## 输出

分两轴报告：`## 规范轴` 和 `## 需求轴`，不跨轴合并。
