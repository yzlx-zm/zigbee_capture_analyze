工具简介

Zigbee Capture Analyzer 是一个 Zigbee 抓包离线分析工具： 把网关切出的无线抓包文件（.cubx / .pcap / .pcapng）导入本地分析， 自动解读每一帧并给出网络问题诊断，无需部署服务器、抓包文件不出本机。

它能做什么

页面用途（使用者视角）
导入把抓包文件载入工具；大文件按时间窗拆分成小段；配置解密密钥；查看解析校验结果
诊断自动扫描整段抓包，按常见网络问题逐项给出「正常 / 发现问题 / 无法判定」结论与证据帧，可一键跳转看原始帧
拓扑图形化展示网络里有哪些设备（协调器/路由器/终端）、它们之间的链路与通信路径，可随时间滑块观察链路变化
报文逐帧浏览全部抓包内容，多种条件过滤，点开任意一帧看从物理层到应用层的完整字段解析
节点按设备汇总：厂商/型号、收发的命令类型与次数、邻居表、链路质量；可导出单台设备「画像」
AI 助手右下角浮标；可联网查 Zigbee/芯科官方知识，也可描述问题让 AI 结合当前抓包给出分析（后者需自配 API Key）

典型工作流

  1. 拿到一段「有问题的」抓包（例如设备入网失败、频繁掉线、命令无响应）；
  2. 在导入页载入文件（若文件很大，先用时间窗拆分出问题时段）；
  3. 打开诊断页看工具自动发现了什么（可点卡片里的「报文」按钮跳到具体帧核实）；
  4. 到拓扑页看设备间链路、报文页核对协议交互细节、节点页查设备身份；
  5. 把结论或疑问丢给AI 助手做交叉印证。
提示：工具只做分析，不做现场调试——它不能修改网络，也不连接任何设备。 所有结论都来自你导入的这一段抓包。

安装与启动

2.1 安装（= 解压）

步骤 1 —— 把收到的 ZigbeeAnalyzer-版本.zip 解压到任意目录。 建议放在一个固定位置（例如 D:\Tools\ZigbeeAnalyzer\），不要在压缩包里直接运行。
步骤 2 —— 确认目录里有 ZigbeeAnalyzer.exe 和 _internal 文件夹（依赖与页面文件）。二者要保持在同一目录，移动时整体移动。

工具无需额外安装任何运行库（Python/Node 都不用装），解压即用。 目录放在中文路径（如桌面、D:\测试工具\）也能正常运行。

2.2 启动

步骤 1 —— 双击 ZigbeeAnalyzer.exe。
步骤 2 —— 弹出黑色控制台窗口，同时自动打开默认浏览器进入工具页面 （首次启动准备环境约需数秒）。控制台第一行会打印访问地址（形如 http://127.0.0.1:57231）与版本号。
步骤 3 —— 浏览器没自动打开时，手动把控制台里显示的地址输入浏览器即可。 页面顶部状态栏显示当前版本号（如 v1.0.2）。
退出 = 关闭黑色控制台窗口（或按 Ctrl+C）。 只关浏览器页时工具仍在后台运行，再次双击 exe 会打开新页面连回原实例。
单实例：同时只允许运行一个实例。第二次双击会提示 「工具已在运行，请关闭已打开的窗口（控制台窗）后重试」，这是正常保护，不是故障。

2.3 主界面速览

「⟳ 重启后端」用于极少数页面卡死时的恢复（例如导入超大文件后界面无响应），平时无需使用。

数据目录说明

工具把数据分成两类存放：程序文件（更新时整包覆盖）与个人数据（更新时保留）。 理解这个分层后，升级版本永远不用重新配置。

内容位置更新版本时
程序文件：exe、依赖、前端页面、version.json 你的解压目录\整包覆盖替换
AI API Key 等个人配置（敏感，本地保存） %APPDATA%\zigbee-analyzer\ai_config.json自动保留，不覆盖
运行日志（排障用，自动轮转 2MB×3） %APPDATA%\zigbee-analyzer\logs\app.log保留
手工添加的 Zigbee 解密密钥 %APPDATA%\Wireshark\zigbee_pc_keys保留（与 Wireshark 共享）

%APPDATA% 是系统用户目录（资源管理器地址栏输入 %APPDATA% 回车即可打开）。

为什么要这样设计

  • 升级不丢配置：AI Key 存在用户目录，新版程序文件直接覆盖即可，Key 不会丢；
  • 卸载干净：删除整个解压目录即完成卸载（个人配置目录可按需一并删除）；
  • 解密密钥与 Wireshark 互通：工具读写的是 Wireshark 的标准密钥文件 （zigbee_pc_keys）。你在 Wireshark 里加过的 Zigbee 密钥，工具直接可用； 在工具里加的，Wireshark 解密同一份抓包时同样生效；
  • 日志可查：遇到异常时把 logs\app.log 发给我们即可定位问题。
注意：导入的抓包数据保存在内存中（不上传、不落盘、重启后清空）。 需要留档的分析，用各页面的导出功能（节点画像 / 案例库导出）把结论存到本地。

导入抓包

4.1 支持的文件

格式来源说明
.cubx芯科 Simplicity Studio Network Analyzer / 抓包器导出 推荐格式：含密钥、LQI/RSSI 等附加信息，解析最完整
.pcap / .pcapngWireshark 等 受支持；无 64 位地址等附加信息时会相应少展示

4.2 导入小文件（直接分析）

步骤 1 —— 进入导入页。把文件拖进虚线框（支持多选），或点击虚线框选择文件； 也可以点击「或输入本地路径…」直接粘贴路径（多个用逗号分隔）。
步骤 2 —— 页面出现解析进度条，顶栏同步显示进度。单个 .cubx 在 1MB 以内、以及任意 .pcap 文件都会直接开始整包导入。
步骤 3 —— 完成后显示导入结果卡片：总帧数、设备数、帧类型分布、 解密成功率与校验结果；点「查看拓扑 →」直接进入拓扑页。

4.3 大文件（>1MB 的 .cubx）：时间窗拆分导入

几十上百 MB 的整包抓包（物理帧可达百万级）直接解析会非常慢。 工具对此采用先选时段、再导入该时段的流程：导入单个超过 1MB 的 .cubx 时， 会先快速预扫描（秒级）并弹出时间窗拆分面板，让你只导入感兴趣的时间段。

步骤 1（选窗） —— 在柱状图上，把两侧滑块拖到问题时段附近 （配合时间刻度）或用「精确时间（月-日 时:分）→ 应用」精确输入起点与终点。
步骤 2（拆分） —— 点「拆分子包」。工具物理拆出一个只含该时段的小 .cubx （几秒内完成，可在 Ubiqua 中打开复验）。拆分结果列在面板下方： 窗口 · 帧数 + 「⬇ 下载」（留存/复验）+「导入此子包」。
步骤 3（导入） —— 点「导入此子包」，该时段小包很快解析完成，进入正常分析流程。 可以连续拆多个时段分别导入。
两个备选按钮：「取消（整包导入）」= 不做拆分，直接整包导入（大包将解析很久，请确认需要全量数据）； 「关闭面板（换别的包）」= 放弃本次选择，不导入也不拆。

4.4 解密与密钥管理

Zigbee 数据帧大多带链路层加密。没有密钥时，这些帧只能看到加密概要。 工具已内置常见预设密钥（ZigBeeAlliance09 等），并会自动使用： ① 素材文件自带的密钥（.cubx 常内嵌抓包时的密钥）② Wireshark 系统密钥文件里的密钥。

如何添加密钥 —— 展开「🔑 密钥管理」，把 16 字节密钥粘贴到 Key 输入框（支持 FC:90:D2…、FC90D2… 等写法）， 填个便于识别的标签，点「添加」。列表随即刷新该 Key 的命中统计。
关键提示：解密发生在导入时。若导入完成后发现未解密帧多， 请先补齐密钥再重新导入一次该文件，让新密钥生效到全部帧（见 11.6）。

4.5 解析校验报告

导入完成后工具会自动做一轮解析正确性自检（帧能否按规范正确解读）。 校验结果展示在导入结果卡片上。正常时为「通过」；若校验失败，为保证分析结论可信， 拓扑 / 报文 / 节点三个页面会被锁定并提示原因，回到导入页重新导入即可。 只要看到校验通过，后续分析的数字都是基于可靠解读的。

4.6 清除数据 / 重新开始

导入结果卡片右下角「清除数据」清空当前分析内容（连点两次确认）。 清除后可以导入另一段抓包。同一时间只保留一份数据——分析新的前请先把上一份的结论导出留档。

5

诊断页（自动发现问题）

诊断页是本工具的「体检报告」：导入完成后切到诊断页，工具自动扫描整段抓包， 对照常见网络问题逐项检查。页面上方先选「网络(PAN)」（一份抓包含多个网络时切换查看），再点「⟳ 重新诊断」。

5.1 阅读方法：检测结果视图

每张检测卡长这样

  • 标题：小角标 = 问题编号（内部编号，无需记忆）；正文 = 白话说明，如「密钥分发或验证出问题」； 紧接结论标签——正常 / 发现问题 / 无法判定（不同颜色），以及置信度（高=直接证据 / 中=帧模式 / 低=推断 / 不可判定=数据不足）；
  • 💬 结论：一句话讲人话的结论；
  • 关键计数：判定依据的量化数据（例如验证循环 ×7、失败帧 39 条）；
  • 涉及设备：每台命中设备一行，行尾「🔍 报文」可跳转到报文页定位到相关帧；
  • 📋 证据帧：可展开的帧列表（时间/收发方/命令），是结论的原始依据；
  • 事件链卡片：当多个问题命中同一台设备时，会有一张卡把事件按时间串起来讲（例如「设备入网→验证失败→反复重试→离网」）。
关于「无法判定」：抓包有盲区（如听不到某些信道），没有证据 ≠ 没有问题。 标「无法判定（琥珀色）」表示这段抓包不足以得出结论，请结合现场复测。

5.2 场景学习视图（案例库）

检测卡片基于协议规则自动判读。当遇到工具还不会自动判读的疑难问题时， 可以把这段抓包标成一个案例入库；下次导入同类问题时，工具会在场景学习视图给出 「这个问题以前遇到过」的提示与当时记录，越用越准。

把当前包标为案例 —— 点「➕ 把当前包标为案例」，在弹层里填 现象（出什么问题）、根因（排查结论）、严重度、环境与所属场景（可多选，系统自动预填当前网络），保存后该包入案例库。
口径说明：场景学习的「已学 X/54」指案例库已覆盖的场景数；每个场景下的案例会带 「证据置信度」——案例越多、越一致，参考价值越高。案例只在本机或你主动导出的 zip 内，不会上传。
6

拓扑页（网络结构图）

拓扑页把抓包中「活跃的设备与链路」画成一张图：一眼看出谁在跟谁通信、走哪条路径。 图上方是拓扑统计与工具条，点「📖 图例」随时对照图形含义。

6.1 节点与形状

  • 形状 = 设备类型：协调器 / 路由器 / 终端设备 / 未知设备（自动按协议行为判定）；
  • 标签两行：第一行短地址（如 0x838D），第二行型号（从设备上报的身份读取，如 AKLOCK-C6）；
  • 颜色与图标 = 当前状态：正常 / 🔄 重连中 / 💤 休眠 / ⏻ 离线 / 静默（有记录但当前无活动，可隐藏）；
  • 鼠标悬停显示详情（厂商/型号/EUI64/轮询间隔/收发帧量等），单击高亮该节点与相关链路，双击聚焦放大。

6.2 链路（边）

  • 数据流：两设备间发生过直接通信；
  • 路由路径：经过中间节点转发的通信路径（实线=当前路径，虚线=历史路径）；
  • 父链路：由轮询 / 入网应答 / 下行投递证据确定的「谁挂在谁下面」的关系。
链路是「画出来的证据」而非猜测：每条边都来自抓包中的协议证据（轮询父节点、 路由请求/应答、下行路径等）。没有证据的节点会标「◌ 未关联」。

6.3 时间游标：观察链路变化

图上方的「⏱ 时刻」滑块把整段抓包按时间展开。拖动游标，图上显示该时刻的链路： 谁当时在通信、父链路当时指向谁。配合底部的「🕐 链路历史」面板（每台设备的链路变更分段时间线， 悬停色块看路径、点击高亮当时的链路），可以回答「这条路是什么时候从 A 换到 B 的」这类问题。

6.4 图例与其它

  • 🔍 节点搜索：输入地址/型号/厂商过滤，点击结果聚焦该节点；
  • PAN 列表：多网络抓包切换查看对象；行内「→TL」跳到报文页过滤该网络；
  • 不对称链路表：列出「A→B 与 B→A 帧数差异大」的链路（信号单向可见，常与抓包位置相关）；
  • 静默节点：可隐藏只出现在某个时刻的设备，聚焦长期活跃成员。
7

报文页（逐帧查看）

报文页是原始抓包列表——诊断卡里点「🔍 报文」也会跳到这里。 左侧是帧列表，点击任意一帧，右侧显示该帧从物理层到应用层的完整字段解析。

7.1 帧列表与摘要

列含义
帧号抓包内的帧序号
时间相对开始时间（时:分:秒）
摘要该帧干了什么（如 Beacon、MAC Ack、命令名），附事件徽章（⛔ 离网 / 🔄 重入网 / ⚠️ 网络状态等）
路径从源到目的经过的转发链（可展开看完整路径）
NWK Src / Dst网络层源 / 目的短地址
APS Ctr应用层计数器（同一事务的帧计数器相同）
行颜色 = 协议层次（MAC 帧 / 网络命令 / 应用帧等分色，图例见页面说明）。 安全帧未解密的行默认隐藏（见 7.3 开关），需要时再展开。

7.2 详情面板

  • 未解密帧只显示加密层概要（密钥类型/序号等），看不到应用内容——需密钥后重新导入（见 4.4）；
  • 命令帧会标注协议语义（如 Read Attributes、Default Response），应用层载荷尽量解析为可读字段（控制命令、属性读写、DP 数据等）；
  • 摘要徽章行与帧首部信息区给出该帧在网络事件中的角色。

7.3 过滤与查看

过滤条 —— PAN（网络）、节点（短地址）、时间 （开始~结束，支持到时:分:秒的精确输入）、类型（下拉列出当前包实际存在的帧类型，动态生成）—— 任意组合后点查询。
🔒 未解密开关 —— 勾选「🔒 未解密」时列表显示加密但未解密的帧； 取消勾选则只显示已解读出内容的帧。未解密帧数多 = 缺密钥（见 FAQ 11.6），不是工具坏了。

9

AI 侧边栏助手

任意页面右下角都有 🤖 浮标，点击打开 AI 助手。它提供两种能力，是否需要 API Key 不同：

能力做什么是否需要 Key
知识检索你的问题若是「这是什么 / 原理 / 怎么做」——联网检索芯科官方文档库，返回相关条目与官方链接不需要
对话分析问题里带上包、地址、时间等范围时——先解析范围、自动整理该范围的统计与事件摘要，再交给大模型结合抓包内容回答需要（自配）

9.1 配置 API Key（可选，仅对话分析需要）

隐私说明：Key 只保存在本机（打包版存 %APPDATA%\zigbee-analyzer\ai_config.json），不随包分发、不上传任何服务器； 对话分析时发送给大模型的是当前抓包的统计与帧摘要（脱敏），抓包原始文件不发送。
未配置 Key 时：知识检索照常可用；输入分析类问题时，AI 会提示去设置里配置 Key。 不知道填哪个 Key：向你们团队的 AI 平台管理员索取（支持 Anthropic / OpenAI / DeepSeek 兼容端点）。

9.2 其它功能

  • 历史：侧栏的对话历史（本机保存，刷新不丢）；「＋」开新会话；
  • 回答里的帧引用：分析回答中提到的帧可直接点击跳转到报文页对应帧；
  • 面板右下可拖动改变宽度，顶栏「─」折叠。

版本更新

步骤 1 —— 拿到新版压缩包 ZigbeeAnalyzer-新版本.zip。
步骤 2 —— 先退出正在运行的工具（关闭黑色控制台窗口）。
步骤 3 —— 用新版文件覆盖旧解压目录（解压时选择「全部覆盖」； 或删除旧目录后解压新版，推荐后者，最干净）。
步骤 4 —— 双击新 exe 启动，页面顶栏显示新版本号即成功。
数据保留：如上覆盖只动程序目录——AI Key 配置与日志在 %APPDATA%\zigbee-analyzer\，解密密钥在 %APPDATA%\Wireshark\zigbee_pc_keys，全部自动保留，无需重新配置。 案例库等个人导出的文件建议更新前先备份。

怎么确认当前版本：页面顶栏右侧「v版本号」（如 v1.0.2）； 或打开解压目录里的 version.json 查看。

不要把新版文件直接解压到旧目录中的子文件夹里（会变成新旧混放）。 要么整体覆盖同一层目录，要么删旧解新。

常见问题 FAQ

11.1 杀毒软件报警 / 无法运行

PyInstaller 打包的绿色程序没有商业数字签名，部分杀软（尤其 Defender）可能误报。 属正常现象：请为解压目录添加信任 / 排除项后重新解压运行。 若已被隔离，先恢复文件再排除。工具本身只在本机解析抓包，无联网上传行为 （唯一联网项是 AI 知识检索，且失败时不影响其它功能）。

11.2 双击 exe 没反应 / 页面打不开

  1. 等 3~5 秒——首次启动在准备环境，可能无窗口闪烁；
  2. 确认没有旧实例未关闭（弹「工具已在运行」= 有旧实例，任务管理器结束旧进程或重启电脑）；
  3. 杀软可能拦截了启动——把目录加入排除项重试；
  4. 控制台窗口里有报错信息，或日志文件 %APPDATA%\zigbee-analyzer\logs\app.log 有记录时，把内容发给支持人员。

11.3 端口被占用 / 控制台显示端口错误

工具默认自动挑选空闲端口，一般不冲突。若看到端口相关报错，通常是旧实例残留： 关闭所有控制台窗口后重试。页面顶栏「⟳ 重启后端」可在页面卡死时恢复后端，无需重启整个工具。

11.4 日志在哪里

%APPDATA%\zigbee-analyzer\logs\app.log （文件较大时已自动轮转，保留最近 3 份）。报障时请附带该文件。

11.5 AI 知识检索提示「知识源不可达（需联网）」

知识检索需要联网访问芯科官方文档服务。内网 / 断网环境不可用，属预期： 其余全部功能（导入/诊断/拓扑/报文/节点）离线可用，不受影响。

11.6 报文里「未解密」的帧很多

安全帧必须匹配到正确的网络密钥才能解密。未解密多通常是：

  • 该网络使用非标准密钥且未提供 → 拿到设备/网关切出的密钥，在导入页密钥面板添加后重新导入（解密发生在导入时）；
  • 使用标准密钥（如 ZigBeeAlliance09）或素材自带密钥时工具会自动使用；
  • 个别帧连密钥类型都无法识别属正常（见报文页「🔒 未解密」开关可隐藏）。

11.7 中文路径支持吗

支持。工具在中文目录 / 桌面已实测正常运行。若个别系统区域设置下异常， 可改英文路径（多为杀软或系统编码问题，而非工具自身）。

11.8 大包导入很慢 / 卡住

几十 MB 的 .cubx 物理帧可达百万级，整包解析耗时数分钟属正常。 正确姿势：使用时间窗拆分（见 4.3）只导入问题时段（秒级完成）。 若进度条长时间不动（超过 10 分钟），点顶栏「⟳ 重启后端」后重试。

11.9 诊断说「无法判定」是没分析出来吗

不是。没有证据 ≠ 没有问题：单点抓包有覆盖盲区（听不到其它信道 / 其它频段）， 无法判定表示这段抓包里看不到足以裁定的证据，请结合现场复测或多点抓包。

11.10 可以分析多台网关 / 多个网络的抓包吗

可以。一份抓包里含多个网络时：诊断页 / 拓扑页 / 报文页均有网络(PAN)选择器， 先选目标网络再分析，避免串网误判。节点页展示全部网络设备（每台标注所属）。

11.11 我的抓包能在别的机器上复现吗

可以。把 .cubx/.pcap 原文件发给对方即可（解密密钥如有自配，一起告知）。 案例库支持导出 zip（含素材副本），导入后「场景学习」内容完整迁移。
