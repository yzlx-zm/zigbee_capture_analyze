# UI 窗口功能分配 (UI Page Responsibilities)

> 2026-08-04 | wayfinder ticket 06 | 目的: 每个导航页的职责边界清晰, 功能不重复不缺失

## 导航结构

```
📡 Zigbee 拓扑分析
[导入] [拓扑] [时间线] [节点] [诊断] [AI]
```

## 各窗口职责

| 页面 | 职责 | 主要数据源 | 状态 |
|------|------|-----------|------|
| **导入** | 数据入口: 抓包导入 (cubx/pcap/csv) / 密钥管理 / 数据校验报告 / 清除数据 | /api/import/* | ✅ 现有 |
| **拓扑** | 网络结构: 节点图 (Cytoscape) / 路由路径 / PAN 过滤 / 邻居关系; 待办: 时间窗口控制 | /api/topology/* | ✅ 现有 + ticket 02 |
| **时间线** | 帧流视图: 按时间筛选/跳转, 事件标记 (Leave/Rejoin/Announce/NetworkStatus) | /api/packets | ✅ 现有 |
| **节点** | 设备详情: 设备列表/搜索 / 邻居表 / LQI-RSSI / 地址映射 | /api/nodes | ✅ 现有 |
| **诊断** | 场景检测结果: L1-L7 检测卡片 (L1-1/2/3/4 现有) + 设备离线诊断 (Leave 波次/重入网) | /api/diag/* | ✅ 现有, L1-4 已对齐 |
| **AI** | 自然语言分析 (规划中) | — | ⏳ 占位 |

## 联动关系 (跨页跳转)

- 诊断 → 设备详情 → 拓扑高亮 (规划)
- 时间线 → 帧详情 → 诊断定位 (规划)
- 导入 → 校验通过 → 拓扑/时间线解锁 (已有: verifyPassed 锁定机制)

## 诊断页内部区块

```
🩺 网络诊断
├── 🔍 L1 入网检测区    ← L1-1/2/3/4 四卡片 (统一 .l1-card 样式)
├── 📊 设备离线总览     ← 统计 (离网/被踢/主动/重入网)
└── 📋 每设备诊断卡     ← 时间线 (正常→Leave波次→重入网) + 诊断结论
```

## 视觉规范 (2026-08-04 统一)

- L1 卡片: `.l1-card` (白底/圆角6px/细边框), 标题+置信度 `.conf`, 数据 `.body`, 设备明细 `.dev`
- 状态色: 绿 `#16a34a` (HEALTHY) / 红 `#dc2626` (HIT) / 琥珀 `#f59e0b` (INCONCLUSIVE)
- 设备地址: monospace, 置信度带 title 提示
