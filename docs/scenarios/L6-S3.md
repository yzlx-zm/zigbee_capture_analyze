# 场景 L6-S3：间接事务过期（SED 消息送不出/取不到）

> 模板：ADR-0002 场景拆解模板（14 层）| 分类：L6 SED 专项 | 状态：**v1.0（官方依据 + G32 素材实证：R1/R2 验证通过；经典 SED 睡眠型待素材）**
> 官方依据：
> - 0x06 语义：`message.h` `sl_zigbee_incoming_route_error_handler`（SL_STATUS_MAC_INDIRECT_TIMEOUT：
>   "message sent to the target end device could not be delivered by the parent because the
>   indirect transaction timer expired"；收到后栈为目标设备设置 extended timeout）
> - 间接传输机制：SED 的父节点缓存消息（间接队列）→ SED poll → MAC ACK Frame Pending 位 → SED 继续 poll 取数据
> - 间接超时默认：EMBER_INDIRECT_TRANSMISSION_TIMEOUT 7.68s（L2-1 文档已确认）
> ⚠️ **状态声明**：判定规则框架由官方机制确认；**G32 素材实证"下行投递失败"型（poll 频繁仍过期）**；
> 经典"SED 睡眠过久未 poll"型待素材（标注 **[待素材]**）。

---

## 0. 抓包可行性（数据现实层）— ✅ 已确认（含素材实测）

| 条件 | 要求 | 说明 |
|------|------|------|
| **最小抓包时长** | 覆盖间接超时窗口（7.68s）+ 多轮过期事件 | 素材实测：38 次过期跨 24 分钟 |
| **sniffer 位置** | **父节点↔SED 链路** | poll（MAC 层）与 0x06（NWK 层）都需覆盖；sniffer 不在则 poll 统计失真 |
| **MAC 帧可见性** | **✅ 素材实测：DataRequest (MAC cmd 0x04) 可提取** | G32 0xEE48 poll ×1933 全提取 |
| **间接队列内部状态** | 抓包看不到父节点队列内容 | 0x06 是"过期"的外部信号；消息内容不可见 |
| **0x06 生成者** | 父节点生成（间接消息持有者） | 素材实证：0xBE5A（父）→ 0x0000 报告，dest=0xEE48 |

---

## 1. 场景识别（入口）

**用户描述关键词**：`消息收不到`、`命令丢失`、`SED 收不到下发`、`睡眠设备丢消息`、`间接超时`、`INDIRECT_TIMEOUT`、`0x06`、`设备 poll 了但没收到数据`

**典型症状**：
- 睡眠终端设备（SED）收不到网关下发的命令/数据（但 poll 正常）
- 网关侧：发给 SED 的消息超时失败（日志 `MAC_INDIRECT_TIMEOUT`）
- 父节点侧：0x06 Network Status 报告间接消息过期
- 设备可能在线（poll 活跃）但消息就是送不到

**与相邻场景的区分**（详见第 7 层）：
- 间接队列满（未缓存）→ **0x05 NO_INDIRECT_CAPACITY**
- 下行路由失败 → **L3-5**（0x0B/0x0C）——G32 案例 0x06 与 0x0C 并存（交叉）
- 设备根本不 poll（睡眠太久）→ L2-1（poll 间隔超时被移除）

---

## 2. 正常抓包基线 — ✅ 官方机制确认

**SED 间接传输机制**（官方，docs.silabs.com End Devices and Polling）：
```
① 协调器/其他设备 → SED 发单播 (消息到父节点, 父节点缓存到间接队列)
② 父节点间接队列持有消息, 超时 EMBER_INDIRECT_TRANSMISSION_TIMEOUT (默认 7.68s)
③ SED poll (MAC Data Request) → 父节点 MAC ACK 带 Frame Pending 位
④ SED 看到 Frame Pending → 继续 poll 取数据 → 消息送达
⑤ 若 SED 在超时内未取走 (没 poll 或 poll 没触发投递) → 消息过期, 父节点生成 0x06
```
**健康行为**：SED 正常 poll（间隔 < 7.68s）时消息被取走，无 0x06；0x06 是"取走失败"的信号。

**G32 素材实测（0xEE48 健康 poll 参照）**：poll 间隔 p50 0.5s / p90 6.0s —— 远小于 7.68s 间接超时（正常节奏）。

---

## 3. 异常表现 — [官方确认 + G32 素材实证]

| 观察点 | 正常 | 异常（本场景） |
|--------|------|----------------|
| Network Status 0x06 | 无 | **出现**（父节点报告间接消息过期） |
| 0x06 生成者/目标 | — | 素材：父 0xBE5A → 0x0000 报告，dest=0xEE48 ×38 |
| 目标设备 poll | 正常取走消息 | **poll 频繁但消息仍过期**（G32：poll 后平均 2.5s 就过期!） |
| 伴随 0x0C | 无 | G32：0x0C dest=0xEE48 ×86 并存（**下行投递失败**） |
| SED 睡眠行为 | 正常 poll | 经典型：poll 缺失/间隔 >7.68s（[待素材]） |

**G32 实证形态（2026-08-05）**：0xEE48 poll ×1933（间隔 0.5-6s，节奏正常），但 0x06 在 poll 后
**平均 2.5s** 就报告过期——poll 没有触发消息投递 → **下行投递失败**（父节点收到 poll 但送不出数据）。
与 0x0C（dest=0xEE48 下行失败 ×86）完全吻合 → **0x06 是 L3-5 下行失败的 SED 侧表现**（交叉场景）。

## 4. 判定条件（可编程规则）— 规则框架已确认（grilling 定稿 2026-08-05），经典型待素材

```
规则 L6-S3-R1（0x06 记录, 高置信, 官方语义直接）:
  network_status code == 0x06 (INDIRECT_TRANSACTION_EXPIRY)
  → L6-S3 命中 (父节点间接消息过期 — 消息未在间接超时内送达 SED)
    官方: message.h SL_STATUS_MAC_INDIRECT_TIMEOUT; 生成者 = 父节点
    素材: G32 0xBE5A→0x0000 ×38, dest=0xEE48

规则 L6-S3-R2（形态细分, 素材实证 2026-08-05）:
  0x06 出现
  AND 目标 SED poll 活跃 (有 DataRequest, 间隔 < 7.68s)
  → **下行投递失败型** (poll 在但消息送不出 — 与 L3-5 交叉, G32 实证)
    判定: 0x06 距最近 poll < 7.68s 且 poll 间隔正常 → 投递失败
  AND 目标 SED poll 缺失/间隔 ≥ 7.68s
  → **SED 睡眠型** (经典: 设备没及时 poll — [待素材])

规则 L6-S3-R3（与 0x05 区分, 官方语义）:
  0x05 (NO_INDIRECT_CAPACITY) = 间接队列满, 消息未缓存 (不同信号)
  0x06 = 消息已缓存但过期 (本场景)
  → 0x05 单独记录, 不混入 L6-S3 判定 (队列容量问题)
```

**关键字段**（官方确认）：
- 0x06 生成者 = 父节点（间接消息持有者）；dest 字段 = 目标 SED
- 间接超时默认 7.68s（EMBER_INDIRECT_TRANSMISSION_TIMEOUT）
- poll 帧 = MAC Data Request（cmd_id=0x04）；Frame Pending 位在 MAC FCF

## 5. 直接证据（铁证）— ✅ 官方确认

| 优先级 | 证据 | 说明 |
|--------|------|------|
| ★★★ | Network Status 0x06（父节点报告间接过期） | 官方 message.h → **R1** |

| ★★ | 伴随 0x0C（dest=同一 SED） | G32：0x0C dest=0xEE48 ×86 → 交叉 L3-5 |
| ★★ | SED poll 缺失/间隔 >7.68s | 经典睡眠型 [待素材] |

## 6. 根因链路 — [官方部分确认]

```
表象: SED 收不到下发消息 / 网关消息超时
  ├─ 直接原因 1: 下行投递失败 (poll 在但送不出) ← G32 实证形态
  │    ├─ 深层: 父节点↔SED 下行链路断 (0x0C 交叉) — 关联 L3-5/L3-9
  │    ├─ 深层: 父节点间接队列处理异常 (收到 poll 未触发投递)
  │    └─ 表现: R2-投递失败型 (0x06 + poll 活跃)
  ├─ 直接原因 2: SED 睡眠过久未 poll (经典型)
  │    ├─ 深层: 睡眠配置/电池/死机 — 关联 L2-1
  │    └─ 表现: R2-睡眠型 (0x06 + poll 缺失) [待素材]
  ├─ 直接原因 3: 间接队列满 (消息未缓存) — 关联 0x05
  │    └─ 表现: R3 区分 (0x05 ≠ 0x06)
  └─ 交叉: G32 案例 0x06 是 L3-5 (0xBE5A↔0xEE48 下行失败) 的 SED 侧表现
```

## 7. 混淆项（长得像但不是）— [骨架]

| 混淆场景 | 抓包差异 | 排除方法 |
|----------|----------|----------|
| **L3-5 源路由/MTORR 失败** | 0x0B/0x0C 为主；0x06 可能伴随 | G32：0x06 是 0x0C 下行失败的 SED 表现 → **交叉双报**，根因在 L3-5 |
| **0x05 间接队列满** | 0x05 ≠ 0x06（未缓存 vs 过期） | code 区分（R3） |
| **L2-1 终端频繁离线** | 设备 poll 缺失/超时被移除（Leave/Rejoin 循环） | 看 poll 是否活跃：活跃 → L6-S3 投递失败型；缺失 → L2-1 |
| **设备主动收不到（路由层）** | 无 0x06（消息根本没到父节点） | 有 0x06 = 已缓存已过期；无 = 路由层问题 |

## 8. 自动检测盲区 — [官方确认]

| 盲区类型 | 本场景表现 | 后果 |
|----------|-----------|------|
| **poll 帧可见性** | poll 是 MAC 单播，sniffer 不在链路则丢 | poll 统计不准 → R2 形态误判 |
| **间接队列内部** | 看不到队列内容/投递尝试 | 0x06 是唯一外部信号 |
| **"poll 收到与否"盲区** | sniffer 看到 poll 发出 ≠ 父节点收到 | 投递失败型 vs 父节点收不到 poll 无法帧级区分 |
| **经典睡眠型素材** | 无 0x06 + 无 poll = 静默 | 需 0x06 素材才能判（当前仅投递失败型） |

## 9. 置信度分级 — [框架确认]

| 置信度 | 判定条件 | 复核建议 |
|--------|----------|----------|
| **高** | 0x06 出现 + 目标 SED + 生成者父节点（R1） | 直接定位父节点↔SED 链路 |

## 12. 判定示例（真实抓包）— 示例 A ✅ G32 实证 / 示例 B 待素材

### 示例 A：下行投递失败型 ✅（G32_0626.cubx, 2026-08-05 实证）

```
0x06 ×38: 0xBE5A (父) → 0x0000 报告, dest=0xEE48, 跨 24 分钟
0xEE48 poll ×1933 (间隔 p50 0.5s / p90 6.0s — 节奏正常)
0x06 距最近 poll: 平均 2.5s (max 6.4s) — poll 刚发生消息就过期!
伴随: 0x0C dest=0xEE48 ×86 (下行失败)
→ L6-S3-R1 命中 + R2 投递失败型 (poll 活跃仍过期)
→ 交叉提示: 0x06 是 0xBE5A↔0xEE48 下行失败 (L3-5) 的 SED 侧表现
→ 根因指向: 0xBE5A 收到 poll 但无法投递数据 (下行链路/队列异常)
```

### 示例 B：（待素材）经典睡眠型

**条件**：0x06 出现 + 目标 SED poll 缺失或间隔 ≥7.68s（设备睡眠过久未取消息）。
**候选素材**：SED 睡眠配置异常的现场抓包。
