## 实现要点 (总控设计)

### 1. 打包脚本 — build.py (新, 主工程 tools/ 或根目录)
- 参数: `python build.py [--version X.Y.Z]` (默认自动: git describe + 日期)
- 流程: 清理 dist → PyInstaller (spec 或命令行) → 生成目录包 → 写 version.json →
  打 zip (工具名-版本号.zip) → 输出体积/文件清单
- spec 要点: onedir; frontend 静态文件作为 datas 打进 (MEIPASS 路径验证);
  隐藏导入: scapy (全部 layers)/Crypto/uvicorn 相关; exclude 测试/scratch
- 启动信息: 控制台标题 + 版本号显示

### 2. 数据分层实现
- 程序目录 (更新覆盖): exe/_internal/frontend/version.json + zigbee 密钥相关 (cubx 内嵌
  自动, zigbee_pc_keys 系统级照读)
- 用户级 %APPDATA%\zigbee-analyzer\: ai_config.json (U17 key) + logs/
- config.py 扩展: 打包后识别用户级数据目录 (APP_DATA_DIR), 非打包模式用原路径 (兼容开发)

### 3. 单实例锁
- 启动时锁 (互斥名/端口文件): 已运行 → 提示"工具已在运行"并退出 (或聚焦已有实例)

### 4. 离线/日志
- 离线检测: AI 知识检索请求失败 → "知识源不可达 (需联网)" 提示, 不崩
- 日志: logging 配置 → data/logs/app.log (轮转)

### 5. 文档
- 分发 README: 使用说明 (双击/数据目录/更新方法/杀软误报说明/卸载=删目录)

## 验证标准 (打包产物实测清单)

## 风险

- PyInstaller 隐藏导入遗漏 (scapy 层/加密 DLL) → spec 里显式声明 + 实测启动
- onedir 的 _MEIPASS 路径 = _internal — frontend datas 位置验证 (启动后首页 200)
- 杀软误报 (目录包较低, 分发说明里提示)
- 体积: 预计 150-250MB (zip 60-100MB)
- AI key 迁移: 已配 key 的用户更新后路径不变 (同 %APPDATA%), 无迁移问题
