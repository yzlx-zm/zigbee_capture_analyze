## 1. 场景识别（入口）

**用户描述关键词**：`状态不同步`、`灯开了但 APP 显示没开`、`上报慢`、`状态一直不变`、`刷新才更新`

**典型症状**：
- 控制命令执行成功（设备有响应），但状态属性上报延迟 >10s 或缺失
- APP 显示状态与实际不符（滞后/不一致）
- 设备周期性上报间隔异常大（maxInterval 配置问题）

**与相邻场景的区分**：
- 命令无响应 → **L3-1**（送达层）；有错误响应 → **L3-2**（执行层）
- L3-3 是**执行成功后**的状态同步层（上报缺失/延迟）
- 设备完全沉默（长时间）→ **L2-6 静默失联**（L3-3 是短窗观察）

## 2. 正常抓包基线 — ✅ 官方流程确认

```
正常: 协调器 Write Attributes → Write Attr Rsp (status=0) → 设备状态变化
      → Report Attributes (0x0A) 立即/短间隔 (<1s, playbook P1-3) 上报状态
上报触发 (官方 reporting.c): 属性变化 + minInterval 已过 或 maxInterval 到
素材基线: 中继素材 Write 成功 → 上报 0.0-4.9s (中位 0.1s 上报周期设备)
```

## 4. 判定条件（可编程规则）— 规则框架确认（MCP 核对 2026-08-12）

```
R1 状态上报滞后候选 (中置信):
    Write Attributes (协调器→设备) 成功 (Write Attr Rsp status=0 或未被拒)
    且 设备在 Write 后首个 Report Attributes (任何 cluster) 间隔 >10s
    → 滞后候选 (taxonomy 阈值)
    ⚠️ 前提 1: Write 被拒 (0x86 等) → 状态未变, 不上报正常 (第七次负例实证)
    ⚠️ 前提 2 (自审修正): **设备级沉默**判定, 不要求同 cluster —
       Basic 等属性上报稀疏 (0xCE93: Write Basic 后 15.4s 才 Basic Report,
       但设备 4.9s 已在 On/Off/Color 上报 — 同 cluster 匹配会误报)
R2 无上报 (弱信号, 不单独触发):
    Write 成功 300s 无任何上报 → 状态不一致候选
    ⚠️ 设备可能未配置上报 (无 Configure Reporting) — 需现场确认
```

**判定参数**（待素材校准）:
- R1 阈值 >10s（taxonomy 定义）；观察窗口 300s
- 设备级收敛 ≥2 次滞后（排除单次偶发）

## 6. 根因链路 — [官方确认]

```
状态上报滞后
├─ 上报配置缺失: 设备未配置上报 (无 Configure Reporting / 绑定缺失)
│   └─ 需现场确认 (设备出厂配置 / 网关配置流程)
├─ maxInterval 配置过大: 周期性上报间隔长
├─ 设备固件: 属性变化未触发上报 (reportableChange 阈值 / 固件 bug)
└─ 设备静默: 上报帧丢失/设备失联 (与 L2-6 交叉)
```

## 7. 混淆项（长得像但不是）— [骨架]

| 混淆项 | 区分 |
|--------|------|
| Write 被拒 (0x86) | 状态未变 — 不上报正常（第七次负例） |
| Basic 等稀疏属性上报 | 设备在其他 cluster 活跃上报 = 非滞后（0xCE93 教训） |
| 上报周期相位 | Write 恰好错过设备周期上报 — 需对比设备上报基线（中位间隔） |
| 读属性响应 (Read Rsp 0x01) | 非上报 — 只统计 0x0A |
| 设备失联 (L2-6) | 长时间静默 vs 短窗无上报 — 窗口区分 |

## 自审记录 (2026-08-12)

1. **同 cluster 匹配误报**: 初版要求 Write 与 Report 同 cluster — 0xCE93 案例（Write Basic 后 15.4s 才 Basic Report，但设备 4.9s 已在 On/Off/Color 上报）— Basic 属性上报稀疏，同 cluster 匹配误报 → 改**设备级沉默**判定（Write 后设备完全无任何上报）。
2. **Write 被拒排除**: 第七次 Write 全被拒（0x86）→ 不上报正常 — 需排除（状态没变）。
3. **frame type 守卫缺失 (二次自审)**: 素材实测 56 条 cluster-specific 0x02 被误当 Write（与全局 Write Attributes 同 ID）→ 解析器新增 zcl_frame_type 字段（cubx/tshark 双路径），检测器要求 frame_type=0。
4. **Write 重传未去重**: 素材 107 条 Write 去重后仅 35 事务（72 条重传）→ lag_count 虚高 — 按 (nwk_dst, aps_counter) 去重。
5. 修正后四素材全 HEALTHY（不误报），正例待素材。
