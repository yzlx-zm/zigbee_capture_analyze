## 1. 场景识别（入口）

**用户描述关键词**：`命令发下去了设备没反应`、`设备不执行`、`配置失败`、`属性写不进去`、`设备拒绝`

**典型症状**：
- APS Ack 正常（命令送达），但 ZCL 响应携带错误 status（0x86 属性不支持 / 0xC3 不支持簇 / 0x01 失败）
- 网关写属性/读属性被设备拒绝（配置失败）
- 设备对特定簇命令回"不支持"

**与相邻场景的区分**：
- 无任何响应 → **L3-1**（命令无确认）
- 有错误响应 → **L3-2**（命令送达未执行）— 设备应用层拒绝
- 伴随 0x0B/0x0C → 路由层（L3-5），先解决路由再谈应用层

      （设备执行并确认）

## 3. 异常表现 — [官方确认 + 素材实证]

| 表现 | 官方依据 | 素材实证 |
|------|---------|---------|
| Write Attr Rsp status=0x86 (属性不支持) | 0x86=UNSUPPORTED_ATTRIBUTE（官方枚举） | 第七次 ×16（含 0xFFDE 厂商属性被拒）/ 中继 838D 等 ×52 |
| Default Rsp status=0xC3 (不支持簇) | 0xC3=UNSUPPORTED_CLUSTER | 协调器对设备簇命令 ×3-6 |
| Read Attr Rsp status=0x86 | 同上 | 第七次 ×3 |

## 4. 判定条件（可编程规则）— 规则框架确认（MCP 核对 2026-08-12）

```
R1 命令送达未执行 (中置信, 字段级):
    全局命令的 ZCL 响应帧 status ≠ 0
    → 候选"命令送达但设备未执行"
    status 分类:
      0x86 属性不支持 → 应用层固件/配置问题 (协调器写设备不支持的属性)
      0xC3 不支持簇 → 设备固件未实现该簇
      0xC0/C1 硬件/软件故障 → 设备内部故障
      0x01 通用失败 → 弱信号 (需交叉)
R2 方向细分:
    下行命令 (协调器→设备) 错误响应 = 控制/配置失败 (用户可感知)
    上行 (设备→协调器) 错误响应 = 协调器拒绝设备命令
判定收敛: 同设备错误响应 ≥2 才输出 (排除单帧瞬态)
```

**判定参数**（待素材校准）:
- 设备级收敛 ≥2（三素材命中设备均 ≥2）

## 6. 根因链路 — [官方确认]

```
命令送达但设备未执行 (ZCL 错误 status)
├─ 0x86 属性不支持: 网关写设备不支持的属性 (属性 ID 不匹配/厂商特定属性)
│   └─ 设备固件版本与网关配置不匹配 (设备添加失败场景典型)
├─ 0xC3 不支持簇: 设备固件未实现该簇
├─ 0xC0/C1 硬件/软件故障: 设备内部异常
└─ 0x01 通用失败: 设备侧处理失败 (需设备日志)
```

## 7. 混淆项（长得像但不是）— [骨架]

| 混淆项 | 区分 |
|--------|------|
| 无响应（L3-1） | 无 ZCL 响应 → L3-1；有错误响应 → L3-2 |
| cluster-specific 命令的"首字节" | **非 status**（如 OTA Query Next Image 0x01）— 仅全局命令提取（frame type=0 守卫） |
| Default Rsp 的 command_id | 0x0B 结构 [cmd][被响应命令 ID][status] — status 在 cmd 后 2 字节（自审修正） |
| 路由层失败（L3-5） | 命令根本没送达 → 无响应；L3-2 前提是送达 |

## 8. 自动检测盲区 — [官方确认]

1. **pcap 路径无 zcl_status**（tshark 版本未注册字段）— 待 P5

## 12. 判定示例（真实抓包）— ✅ 素材实证

**第七次素材**: 协调器写属性 → 设备回 Write Attr Rsp status=0x86（属性不支持）×16 — 含 0xFFDE 厂商属性（pid=220/228 等，帧级核实）。**示例 A**: pid=228（0x4372 对写属性回 0x86）。

**直连泛洪**: 协调器回 0xC3/0x86（×7）。
