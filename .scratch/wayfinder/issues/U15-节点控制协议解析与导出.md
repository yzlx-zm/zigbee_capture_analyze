## 实现要点 (总控设计)

### 1. 标准 ZCL 控制簇命令载荷解析 — backend/zcl_defs.py 扩展
- 新增命令载荷结构表: `CMD_PAYLOAD_SCHEMAS[cluster_id][cmd_id] = [field defs]`
  - 按 ZCL 规范: On/Off (0x0006): 0x00 Off(无载荷)/0x01 On(无载荷)/0x02 Toggle(无载荷)/0x40-0x42 Off/On/Toggle With Effect(带 effect 字段)
  - Level Control (0x0008): 0x00 MoveToLevel [level:u8][transition_time:u16]/0x01 Move [mode:u8][rate:u8]/0x02 Step/0x04 MoveToLevelWithOnOff 等
  - 其它标准控制簇按需 (先覆盖常见: On/Off/Level Control/Color Control 0x0300/Door Lock 0x0101 — 素材中出现过的)
- 字段解析: `parse_zcl_command_payload(cluster_id, cmd_id, frame_type, payload_bytes) -> list[{field, value, note}]`
- 严谨: 字段级字节偏移核对 (ZCL spec), 素材验证; 解析失败回退 hex 兜底

### 2. 涂鸦 0xEF00 私有簇解析 — 新文件 backend/tuya_proto.py
- DP 命令结构 (涂鸦公开协议): cmd 0x00-0x1D (DP 上报/下发/查询), 载荷 [dp_id:1][dp_type:1][dp_len:2][dp_value]
- dp_type: 0x00 raw/0x01 bool/0x02 value/0x03 str/0x04 enum/0x05 bitmap
- 解析: `parse_tuya_dp(payload) -> [{dp_id, dp_type_name, value}]` — 附 DP 语义表 (常见 dp_id 含义, 可扩展)
- 素材实证: dimmer 素材 0xef00 cmd11 (Server→Client 上报) / cmd2 需查结构

### 3. 帧解析视图 — 复用时间线详情面板框架
- packet_detail 增强: ZCL 层加 `zcl_payload_parsed` (标准簇/涂鸦/兜底)
- 前端 (timeline.js + nodes.js): 详情面板 ZCL 载荷区显示字段级解析表 (字段|值|说明)
- **节点页**: 控制命令统计表每行加 "📄 示例" 按钮 → 弹帧解析视图 (该命令的代表帧:
  最近一帧或频率最高事务的代表帧; 需后端小端点或前端带参请求 packet_detail)
- 节点页示例取帧: `GET /api/packets?cluster=..&cmd=..&src=..` 或专用端点 (实现时定)

### 4. 节点画像导出 — backend + 前端
- 后端: `GET /api/nodes/{aid}/export` → 生成 JSON + MD (临时文件或直接返回内容)
  - JSON: 画像字段 + endpoints + clusters 统计 + 每命令 1-2 个代表帧的完整分层解析 (含载荷解析)
  - MD: 人读报告 (厂商/型号/端点/簇命令表/帧样本解析)
  - 文件落: 下载目录或返回内容由前端触发下载
- 前端: 节点页行内展开加 "⬇️ 导出画像" 按钮 (JSON/MD 二选一或两文件)

### 5. 兜底与扩展
- 未知簇: 字节偏移拆解 (hex + 索引) — 与用户示例 (Wireshark 式偏移) 对齐
- 解析器注册表: `PAYLOAD_PARSERS[cluster_id] = fn` (标准 zcl_defs → tuya → fallback 链)

## 验证标准

1. 标准簇: 素材中 On/Off / Level Control 命令 → 载荷字段级解析正确 (与 ZCL 规范字节核对)
2. 涂鸦: dimmer 素材 0xef00 帧 → DP 结构解析 (dp_id/type/value)
3. 节点页: 控制命令行"示例"→ 帧解析视图 (分层 + 载荷字段) 弹出示
4. 时间线详情面板: 同帧 ZCL 层显示载荷解析 (与节点页同源)
5. 导出: 节点导出 JSON+MD, 内容含画像+代表帧解析; MD 可读
6. 兜底: 未知簇帧显示字节偏移拆解不崩
7. 回归: 现有详情面板不崩 (无解析 schema 的帧走兜底); P1/P2 不变 (解析器字段只增)

## 风险

- 标准簇 schema 覆盖范围: 先覆盖素材出现簇, 其余按需扩展 (注册表设计保证不崩)
- 涂鸦 DP 结构: 0xef00 命令结构需素材实证核对 (cmd11 上报 vs cmd2 查询载荷不同)
- 帧样本选取: 代表帧策略 (最近/频率最高) 需稳定, 避免每次导出样本不同
- 与 U13/U14 并发: 本 ticket 不动 topo.js, 无冲突; nodes.js/timeline.js 与 U14 无交叠
- 导出文件: 大节点 (多簇多帧) 文件可能大 — MD 精简样本数 (每命令 1-2 帧)
