## 0. 抓包可行性（数据现实层）— ✅ 已确认（含素材实测）

| 条件 | 要求 | 说明 |
|------|------|------|
| **命令帧可见性** | **✅ 素材实测：aps_ack_req 位可提取**（FCF bit6, 与 test-harness 源码一致） | 三素材均有要求 ack 的数据帧（第七次 103 / G32 1148 / 中继 290） |
| **ack 帧可见性** | **✅ 素材实测：ack 帧 8B 完整头 + counter 可提取**（APS 配对能力 cc99542） | ack 帧 counter 沿用原帧 → 字段级配对 |
| **最小抓包时长** | 覆盖 ≥1 次 APS 超时周期（非 SED 1600ms×3≈4.8s; SED +7680ms 间接超时） | 判定窗口 5s 覆盖非 SED 完整重试链 |
| **sniffer 位置** | **盲区：ack 经中继转发回传** — sniffer 不在 ack 路径则"无 ack"是假象 | 与 L3-5 断链盲区同类; 需交叉佐证（0x0B/0x06/重传行为） |
| **重传可见性** | 同 counter 多帧 = 栈内重传（抓包可数） | 栈内 3 次 + 应用层可叠加（社区案例 23 条）→ 数量只做严重度 |
| **SED 特例** | 睡眠终端 ack 由 poll 取回（间接队列） | ack 出现延迟可达 poll 周期; 未设 Extended Timeout → 额外重试/潜在失败 |

**素材无 ack 样本（检测器规则验证基线, 2026-08-06 统计）**:
- 第七次添加失败: 要求 ack 103 帧, **无 ack 47**（0000→C1F5 Basic ×32 等）
- G32: 要求 ack 1148, **无 ack 142**（0000→EE48 Door Lock ×48, 与 L6-S3 同设备交叉）
- 中继入网: 要求 ack 290, **无 ack 78**（0000→838D Door Lock ×34, 与 L3-5 同设备交叉）

## 1. 场景识别（入口）

**用户描述关键词**：`命令没反应`、`控制不了`、`网关发命令失败`、`超时`、`没收到 ack`、`设备没执行`、`DELIVERY_FAILED`、`0x66`

**典型症状**：
- 网关下发命令（读属性/控制/OTA）后长时间无响应 — 应用层无确认
- 网关日志: `EMBER_DELIVERY_FAILED (0x66)`（栈级投递失败上报）
- 抓包: 同一命令同 counter 重复发送（重传）但始终无 APS Ack 回包
- 设备侧: 能上报（上行通）但收不到网关下发 — **与 L3-5 症状重叠, 需 0x0B 区分**

**与相邻场景的区分**（详见第 7 层）:
- 伴随 Network Status 0x0B → **L3-5 源路由失效**（路由层根因）
- 伴随 0x06 间接过期（SED）→ **L6-S3 间接事务过期**
- 设备随后 Leave → **L1-4 / 离线**
- 无任何异常伴随, 单次偶发 → 链路瞬态（低置信）

## 2. 正常抓包基线 — ✅ 官方流程确认

**APS 端到端确认流程**（官方, docs.silabs.com Messaging — Unicast Message Delivery）:
```
① 发送方 APS: [FCF ack_req=1][EP][Cluster][Profile][SrcEP][counter][ASDU]
   → NWK 加密 + 逐跳转发 (每跳 MAC Ack)
② 接收方 APS: 收到数据帧 → 校验 counter → 交给应用
③ 接收方 APS: 回 ack 帧 [FCF type=2][EP][Cluster][Profile][SrcEP][counter=原帧counter]
   → 原路返回 (每跳 MAC Ack)
④ 发送方 APS: 收到 ack, counter 匹配 → 事务完成, 通知应用成功
```
**正常交互的抓包特征**: 每对 (命令帧, ack 帧) counter 相同、方向相反、时间差 <1600ms（非 SED）。

**栈内重试链**（官方 KBA, 数值核对）:
| 层 | 行为 | 失败上限 |
|----|------|---------|
| MAC | CCA 退避 + 等 ACK 864µs, 共 5 次尝试 | ~37ms |
| NWK | 16-48ms 随机退避重发, 窗口 250ms（英文版）/ 500ms（中文版 ⚠️ 版本差异） | 250-500ms |
| APS | 50ms×hops 间隔重发, **3 次尝试**（首+2）; 单次超时 (50ms×30)+100ms=**1600ms**（EmberZNet 3.1+ 可配 EZSP_CONFIG_APS_ACK_TIMEOUT） | 4.8s（非 SED） |
| SED | 目标睡眠 + 未设 Extended Timeout → 每次尝试 +**7680ms** 间接超时 | 最长 27.8s |
| 失败上报 | 无替代路由 → 应用收 **EMBER_DELIVERY_FAILED (0x66)**; RETRY+ROUTE_DISCOVERY 双开则先自动修路 | — |

## 4. 判定条件（可编程规则）— 规则框架已确认（MCP 核对 2026-08-06）

```
R1 无确认命中 (中置信, 字段级):
    数据帧 aps_ack_req=True 且 5s 窗口内无配对 ack (复用 _build_ack_match 反向映射)
    → 候选"命令无确认"帧

R2 高置信 (栈确认失败):
    R1 + 同 counter 重发 ≥2 次 (栈内重传证据, 抓包可见) 且始终无 ack
    → 栈 3 次尝试全部失败 (非 SED 场景近乎铁证)
    ⚠️ 重发次数不做硬阈值 (应用层可叠加, 社区案例 23 条) — 只做严重度信息

R3 交叉归因 (根因方向):
    无 ack 帧伴随 (0x0B 路由错误 → L3-5) / (0x06 间接过期 → L6-S3) /
    (设备随后主动 Leave → 离线) / 无伴随 → 未知 (设备侧/链路瞬态)

R4 方向细分:
    下行 (nwk_src=协调器 → 控制失败, 用户可感知)
    上行 (nwk_dst=协调器 → 上报丢失)

判定收敛: 同设备同方向无 ack 帧 ≥2 次才输出设备级结论 (排除单帧瞬态)
```

**判定参数**（待素材校准）:
- 配对窗口 5s（复用 ACK_MATCH_WINDOW_S, 覆盖非 SED 4.8s 完整重试链）
- R2 重发阈值 ≥2（栈内 3 次尝试的中间状态）
- 设备级收敛 ≥2 次无 ack

| 证据 | 级别 | 依据 |
|------|------|------|
| ack_req=1 数据帧 + 同 counter 重发 ≥2 + 全程无 ack | **铁证**（非 SED） | 栈 3 次尝试全失败才放弃（官方 KBA）; ack 帧 counter=原帧 counter 字段级配对（素材实证） |

## 6. 根因链路 — [官方部分确认]

```
命令无 APS Ack
├─ 路由层: 源路由断/链路断 → 0x0B (→ L3-5, 838D 素材交叉)
├─ SED 层: 睡眠设备间接队列过期/未设 Extended Timeout → 0x06 (→ L6-S3, EE48 交叉)
├─ 设备层: 设备离线/掉电/被移除 → 无响应 (→ L1-4/离线, 第七次 C1F5 场景)
├─ 抓包层: ack 经中继转发, sniffer 不在链路 → 假"无 ack" (盲区, 需交叉佐证)
└─ 链路瞬态: 偶发干扰 → 重传后恢复 (无伴随, 低置信)
```

## 7. 混淆项（长得像但不是）— [骨架]

| 混淆项 | 区分 |
|--------|------|
| 帧未要求 ack（ack_req=0） | 无 ack 是正常, 不判 R1（检测器只统计 ack_req=True） |
| MAC/NWK 层失败 | 链路层重试失败后 APS 才重传; 抓包同 counter 帧全是 APS 重传证据 |
| 广播命令 | 广播无 APS ack（官方）— 只统计单播 |
| 应用层主动重试（新 counter） | 新 counter = 新事务, 不是栈重传; 同 counter 才算重传 |
| 抓包漏 ack（盲区） | 无重发行为 + 无伴随异常 → 中置信以下 |

## 8. 自动检测盲区 — [官方确认]

1. **ack 经中继回传**: sniffer 位置决定 ack 可见性 — 单 sniffer 在协调器侧看不到远端设备的 ack（中继转发）
2. **0x66 不可抓**: 栈内失败上报只出现在网关日志
3. **SED ack 延迟**: 睡眠设备 ack 在 poll 后到达, 配对窗口可能 miss（5s 窗对 SED 场景偏紧, 但"无 ack 判定"仍正确 — 栈已重试）
4. **应用层重传次数**: 抓包可见但归属不可分（栈 vs 应用）

## 9. 置信度分级 — [框架确认]

| 置信度 | 条件 |
|--------|------|
| 高 | R2（重发 ≥2 + 无 ack）+ R3 交叉（0x0B/0x06/Leave 伴随） |
| 中 | R1 + R3 交叉, 或 R2 无交叉 |
| 低 | R1 单帧无伴随（可能抓包盲区） |
| 不可判定 | ack_req 不可提取（pcap 路径字段占位待实证） |

## 11. 上下游关联 — [骨架]

- **L3-5 源路由失效**: 下行无 ack + 0x0B → 根因在路由层（中继素材 838D 交叉）
- **L6-S3 间接事务过期**: SED 下行无 ack + 0x06 → 根因在睡眠机制（G32 EE48 交叉）
- **L1-4/离线**: 无 ack + 设备 Leave → 设备已离开网络
- **L1-3 密钥**: 密钥分发阶段命令无 ack → 入网阶段链路问题
- **L3-11 应用层重传频繁**: 本场景的"应用视角"（新 counter 反复）
