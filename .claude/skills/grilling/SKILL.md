# 核心问答引擎

对嵌入式设计决策、计划或想法进行无情采访，直到达成共同理解。沿着决策树的每个分支走下去，逐一解决决策之间的依赖关系。

## 规则

1. **一次只问一个问题。** 同时问多个问题令人困惑。
2. **每个问题提供推荐答案**——用户可能没有考虑过这些权衡。
3. **从环境探索事实**（文件系统、代码库、`PROJECT-KNOWLEDGE-GRAPH.md`、`CONTEXT.md`、仓库中的数据手册）。查事实而不是问用户。
4. **只把决策交给用户。** 如果能查到，就查。
5. **用户确认共同理解后再行动。**

## 嵌入式上下文

开始前检查：
- `PROJECT-KNOWLEDGE-GRAPH.md`——硬件和软件架构
- `CONTEXT.md`——项目的领域词汇表
- `docs/adr/`——约束当前决策空间的先前架构决策

用这些将问题锚定在项目的现实基础之上。

## 决策跟踪

决策确定后：
- 新术语 → `/domain-modeling` 更新 `CONTEXT.md`
- 难以逆转 + 令人困惑 + 真实权衡 → 通过 `/domain-modeling` 写 ADR
- 所有其他决策 → 捕获在问答会话输出中，输入到 `/to-driver-spec`

## 完成

问答结束当：
- 决策树的每一分支都走完了
- 用户确认共同理解完整
- 所有术语和 ADR 已写入
