## 1. 场景识别（入口）

**用户描述关键词**：`命令一直重发`、`网关反复发同一条命令`、`控制一直失败还在重试`、`命令风暴`

**典型症状**：
- 网关对同一设备反复发送相同命令（新 counter 轮次 ≥3）
- 命令持续失败（无 ack / 被拒 / 无响应）但应用层继续重试
- 与 L3-1（栈重传同 counter）区分：**新 counter = 应用层轮次**

**与相邻场景的区分**：
- 同 counter 多帧 → **L3-1**（栈内重传）
- 新 counter 重复 → **L3-11**（应用层重试）
- 周期轮询（有成功响应）→ 正常，非 L3-11（自审修正）

---

## 2. 正常抓包基线 — ✅ 官方流程确认

```
正常: 命令 (counter N) → 成功响应 (ack / ZCL 成功) → 应用不再重发
栈内: 失败时同 counter 重传 (APS 3 次尝试, L3-1)
应用层: 失败后可自行重试 (新 counter) — 官方无硬阈值; 1-2 次 = 单次失败重试
         (官方预期行为); ≥3 轮 = 重传频繁 (异常信号)
```

---

## 3. 异常表现 — [官方确认 + 素材实证]

| 表现 | 官方依据 | 素材实证 |
|------|---------|---------|
| 同命令新 counter ≥3 轮 | 应用层重试叠加（社区案例 23 条） | test2 0x89F9 Write ×16 轮 (25.2s/轮, 290 帧) / 第七次 0xCE77 ×12 轮 (0.1s/轮) / 中继 0x838D ×12 轮 |
| 密集快速重试 | 应用层无退避（异常） | 0xCE77 0.1s/轮 / 0x8A41 0.1s/轮 |
| 慢速重试（长间隔但持续失败） | 应用层退避重试 | 0x77D0 101.5s/轮 无成功响应 / 0x5285 100s/轮 (Write 被拒仍重试) |
| 周期轮询（有成功响应） | 正常读属性 | 0x4FBC/0xF342 Read 有 Read Rsp → **排除**（自审修正） |

## 4. 判定条件（可编程规则）— 规则框架确认（2026-08-12）

```
R1 应用层重传频繁:
    **同一命令** = 同 (设备, cluster, cmd_id, payload 属性内容) — payload 去 tsn 后
    逐字节相同 (自审修正 2026-08-13: 不同属性 = 批量配置, 非重传)
    该同属性命令 ≥3 个不同 counter 轮次 且:
      排除 1 (轮询): 设备有成功响应 且 帧/轮 <2 (无栈重传迹象) — 正常读/写
      排除 2 (pcap 无 payload 时): 帧/轮 <2 且 长间隔 (>30s) — 属性级不可分, 保守
    → 命中"应用层重传频繁"
    ⚠️ 帧/轮比 = 同 counter 栈重传证据 (≥2 帧/轮 = 每轮在栈层重传 = 真失败重试)
与 L3-1 区分: 同 counter = 栈重传 (L3-1); 新 counter = 应用层 (L3-11)
交叉: 伴随无 ack (L3-1) → 命令持续失败; 伴随错误响应 (L3-2) → 被拒仍重试
```

**判定参数**（素材校准 2026-08-13）:
- 轮次 ≥3（1-2 次 = 官方预期单次失败重试）
- 帧/轮比阈值 2.0（素材: 0x89F9 18.1 真重传 vs 0xBC49 1.36 轮询 分界清晰）
- 密集阈值 30s/轮（仅 pcap 无 payload 守卫用）
- ⚠️ pcap 路径无 payload → 属性级分组不可用（帧/轮比兜底）— 批量配置可能误报（诚实标注）

## 6. 根因链路 — [官方确认]

```
应用层重传频繁
├─ 命令持续失败: 设备无响应 (→ L3-1/L3-5) / 被拒 (→ L3-2) — 应用层反复重试
├─ 设备离线/不存在: 网关对失联设备反复发命令 (test2 0x89F9 案例形态)
├─ 应用层无退避: 快速密集重试 (0.1s/轮) = 应用设计问题 (加剧网络拥塞)
└─ 配置错误: 网关持续尝试配置失败设备 (0x5285 Write 被拒仍 100s 重试)
```

## 7. 混淆项（长得像但不是）— [骨架]

| 混淆项 | 区分 |
|--------|------|
| 栈内重传 (同 counter) | **L3-1** 范畴 — 同 counter 多帧 |
| 周期轮询 (Read 有响应) | 长间隔 + 成功响应 = 正常读 — 排除（0x4FBC/0xF342 实证） |
| 慢速失败重试 (长间隔无响应) | 保留 — 命令持续失败 (0x77D0 101.5s 实证) |
| 单次失败重试 (1-2 轮) | 官方预期行为 — 不判 (≥3 轮) |
| cluster-specific 命令 | frame type 守卫（0x02 同 ID 教训） |

## 8. 自动检测盲区 — [官方确认]

1. **pcap 路径成功响应判定受限**（zcl_status 待 P5）— 长间隔重试 vs 轮询区分弱化
2. **重试原因不可见**: 应用层为什么重试（网关逻辑）— 抓包只见现象
3. **命令语义**: 同命令同 cluster 的重复可能是"批量配置"（正常流程）— 需现场

## 11. 上下游关联 — [骨架]

- **L3-1 命令无确认**: 同 counter 栈重传 — L3-11 的上游失败原因
- **L3-2 命令未执行**: 被拒后仍重试 — 重传的失败上下文
- **L3-5 源路由失效**: 路由层失败 → 应用层重试
- **L2-6 静默失联**: 设备离线 → 网关对失联设备重试

## 12. 判定示例（真实抓包）— ✅ 素材实证（v1.1 修正后基线）

**真重传（帧级核实 2026-08-13）**:
- test2 0x89F9: Write ×16 轮 (290 帧, **18.1 帧/轮** = 栈+应用双重重传风暴, 25.2s/轮)
- test2 0x77D0: Write ×4 轮 (46 帧, 11.5 帧/轮, 101.5s 慢速失败重试)
- 中继 0x8A41: Write ×4 轮 (4.8 帧/轮, 0.1s 密集) + Read ×3 轮 (5.3 帧/轮)
- 中继 0xB75C: Read ×3 轮 **无任何响应** (读不回应的设备)
- 中继 0x5285: Write ×3 轮 (100s/轮) — **被拒 0x86 仍重试** (L3-2 交叉实证)
- 直连泛洪 0x61CD: Read ×13 轮 (16.2s/轮) **无 Read Rsp** (反复读不回应的设备)

**负例（修正排除）**:
- 第七次 0xCE77: Write ×12 轮全**不同属性** (0x24/0x25/0x27... 批量配置) → 排除
- 中继 0x838D: 15 种属性组合 = 网关批量配置断链设备 (L3-1/L3-5 已覆盖失败) → 排除
- test2 0xBC49: Read 28.3s/轮 + 23 帧 Read Rsp = 正常轮询 → 排除
- 0xC1F5 ×32 单 counter = 栈重传 (L3-1 范畴) → 不误报
