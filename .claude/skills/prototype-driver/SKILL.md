# 驱动原型验证

原型是**回答设计问题的一次性固件**。问题决定形态。

## 选择分支

确定要回答哪个问题：

- **"此外设初始化序列/寄存器访问模式对吗？"** → 分支 A：寄存器访问验证
- **"这个时序/ISR 延迟/竞态条件安全吗？"** → 分支 B：时序与竞态验证

### 分支 A：寄存器访问验证

构建**最小固件**：
1. 仅初始化目标外设（无 RTOS，无其他初始化）
2. 每个初始化步骤后 dump 所有寄存器
3. 与数据手册复位默认值对比
4. 执行关键寄存器操作（读/写/读回验证）

约束：
- **一个 .c 文件、一个 Makefile、一条烧录命令**
- 通过调试串口/RTT 打印寄存器状态
- 不要错误处理（超出使固件可运行的必要范围）
- 命名：`<外设>-prototype/`，放在驱动代码旁边

### 分支 B：时序与竞态验证

构建**压力固件**：
1. 以最大速率触发可疑代码路径
2. 在关键决策点翻转 GPIO 供逻辑分析仪捕获
3. 在压力下测量延迟、吞吐量或丢包率

约束：
- GPIO 翻转开销 < 被测时间预算的 1%
- 一条命令烧录，一条命令捕获：`make flash && logic_analyzer_capture`
- 最后打印摘要统计
- 命名：`<场景>-timing-prototype/`

## 两者共同规则

1. **从第一天起就是一次性的。** 用 `prototype-` 前缀命名，让路过的人一眼就看出这不是生产代码。
2. **一条命令构建、烧录、运行。** 工程工具链支持的任何方式。
3. **不持久化。** 状态留在 RAM 中。如果持久化正是被测对象，使用明确标记的临时 flash 区域。
4. **跳过润色。** 无测试、无错误处理、无抽象。目标是快速学到东西。
5. **暴露状态。** 每次操作后，打印/dump/翻转完整的相关状态。
6. **完成后捕获。** 删除原型代码之前：
   - 将验证通过的决策折叠进真实代码
   - 将原型提交到一次性分支（不要合入 main）
   - 在实现工单中引用分支 + 结论
