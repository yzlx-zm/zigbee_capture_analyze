# U12 — 诊断页学习机制 (场景 tab = 学习容器, grilling 对齐产出)

**What to build:** 诊断页从"静态规则检测"升级为"学习机制": 场景 tab 作为学习容器,
导入问题包+标注 → 案例入库 → 场景案例积累 → 结论由案例支撑越来越准 → 导出传播到其他设备。

**Blocked by:** None

**Status:** ready-for-agent

**Type:** task | **AFK**

**来源**: 2026-08-13 总控窗口 grilling 对齐 (用户确认 v2)。
**与第 3 项打包分发联动的接口**: 案例库导出/导入 (本 ticket 先做导出导入文件格式, 打包工具单独对齐)。

## 用户痛点与核心洞察

1. 现有诊断结论卡片"臃肿且准确度不高" — 根因: 结论无真实问题包核对 (闭环缺失)
2. 用户喜欢选项卡形式 — **场景 tab = 学习容器**: "场景问题学习好了, 不就是在不断填充这个场景吗"
3. 学习机制 = 场景被验证案例不断填充 → 结论置信度提升; 未学场景 = "待学习"

## 对齐决策 (用户确认, 不可更改)

| 决策 | 结论 |
|------|------|
| 载体 | 诊断页**选项卡形式保留**, 每场景一个 tab |
| 场景 tab = 学习容器 | 全部 55 场景 (检测器覆盖的显示检测结果; 未覆盖显示"待学习"); tab 内展示该场景已学案例 |
| 学习动作 | 导入问题包 + 标注 (现象/根因/严重度/环境) → PAN/问题设备短地址/时间段**自动提取** (U11 预扫技术复用) → 场景归属 (检测命中 + 人工确认) → 案例入库 |
| 场景命中 | **内置自动判断** (现有 10 检测器), 不人工标期望场景 |
| 结论准确性 | 学好的场景: 结论 = 检测器 + 案例证据列表 (多案例支撑标注置信度); 案例少的场景结论弱化标注"待更多案例" |
| 差距报告 | 检测命中 vs 案例标注对比 → 未对齐 → 待完善清单 → 工单流 → 检测器迭代 → 旧案例重跑验证 |
| 学习进度 | 覆盖提示 "8/55" → **"已学 X/55 场景"** 成长指标 |
| 导出传播 | 案例库数据 + 原始素材副本 → 另一设备导入 → 场景案例同步 → 工具进化 |

## 实现要点 (总控设计)

### 1. 案例库存储 — 新文件 backend/case_library.py
- 目录: `<工具数据目录>/cases/` (与素材台账并列; 建议项目内 `case_library/`, 路径用户确认)
- 每案例一个 JSON: `{id, ts, source_file, material_copy, pan, device_addr, time_range,
  annotation: {phenomenon, root_cause, severity, environment}, detection: {scenario_hits,
  verdicts, evidence}, gap_report, status: new/reviewed/closed}`
- 素材副本: 导入时复制到 `cases/materials/<id>.cubx` (导出传播时自带素材)
- 函数: add_case / list_cases / get_case / find_similar / export_cases / import_cases

### 2. 相似案例检索 — find_similar(packets, k)
- 匹配特征: 检测命中场景集合 (Jaccard) + 根因/现象关键词 (含 Root Cause 同义词表)
  + PAN/设备地址 + 时间窗重叠
- 输出: 相似案例列表 (分数降序, 带标注摘要) — 诊断页"相似历史案例"区
- 简单可迭代: 先关键词+场景集合, 不引入向量化 (后续可迭代)

### 3. 场景 tab 改造 — 前端 diag.js
- 场景 tab 列表: 55 场景 (现有检测器覆盖的 tab 显示检测结果; 未覆盖 tab 显示"待学习: 需案例")
- 每个场景 tab 内: 检测结果卡片 (现有) + **已学案例列表** (根因/现象/严重度/置信度)
  + 案例数徽章 + "添加案例"按钮
- 结论置信度: 案例 ≥N (建议 3) → 标注"多案例支撑"; 案例少 → 结论弱化 + "待更多案例"
- 学习进度: 摘要卡 "已学 X/55 场景" (替代 "8/55 覆盖提示")
- 新包诊断时: 显示相似历史案例区 (来自 find_similar)

### 4. 案例导入标注流程 — 前端 import.js + 诊断页
- 导入问题包时 (或导入后诊断页) 弹标注表单: 现象 (必填)/根因 (可选, 带建议列表)/
  严重度/环境; PAN/设备地址/时间段自动填 (预扫)
- 提交 → 跑检测 → 案例入库 (场景归属: 自动命中 + 人工确认多选) → 差距报告生成

### 5. 差距报告 + 待完善清单 — 后端 API + 前端
- `GET /api/cases/gaps` — 所有案例的检测 vs 标注未对齐项 (未命中/误报/低置信)
- 待完善清单: 场景维度聚合 (哪些场景案例与检测结果不符最多 → 检测器改进优先级)
- 导出/导入 API: `POST /api/cases/export` / `POST /api/cases/import` (复用后台任务)

### 6. 导出传播格式
- 单个 zip: `cases.json` (案例库元数据+标注+检测结果+差距) + `materials/` (素材副本)
- 导入: 解压 → 案例入库 → 场景 tab 案例同步 (检测器规则不随包导出 — 规则是代码,
  代码随工具版本分发; 案例是数据, 可跨版本)

## 验证标准

1. 案例入库: 导入 中继入网抓包(1).cubx + 标注"入网后 2s 被踢/源路由失效" → 案例落盘
   JSON 完整 (标注+自动元数据+检测结果), 素材副本存在
2. 场景归属: 检测命中 L3-5/L1-3/L2-1 自动勾选, 人工可改
3. 相似检索: 用类似问题包诊断 → 返回该案例 (场景集合 Jaccard + 关键词)
4. 场景 tab: 55 tab 齐全; 已学场景显示案例列表+置信度; 未学显示"待学习"
5. 差距报告: 故意标注与检测不符 → 进入待完善清单
6. 导出→导入: 导出 zip → 清空案例库 → 导入 → 案例恢复 (含素材副本), 场景 tab 同步
7. 回归: 现有诊断页检测功能不变 (无案例时行为与现状一致); U11/P1/P2 回归不变

## 风险

- 55 场景 tab 渲染性能: 懒加载 tab 内容 (仅激活 tab 渲染)
- 案例归属歧义 (一案例多场景): 允许多选归属, 差距报告按场景聚合时去重
- 素材副本磁盘占用: 导入时可选"复制素材" (默认复制, 可关闭)
- 导出安全: 案例 JSON 不含密钥 (复用 export_ai_dataset 的 _redact 思路)
- 规模: 本 ticket 范围大, 建议实现窗口按 存储→API→前端→导出 四步推进, 每步验证
