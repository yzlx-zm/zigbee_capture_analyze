## 实现要点 (总控设计)

### 1. 自动生效 (去掉应用按钮)
- 任一框内容变化后校验: **8 格全满且合法 → 自动应用** (同步滑块 + 刷新窗口标签)
- 体验增强: 框内输入满 2 位**自动跳下一格**; 支持 `Enter` 立即尝试应用
- 非法/未满 → 不应用 (保留 `cs-win` 窗口标签不变), 不弹错 (避免边输边报错噪音);
  仅在"看似输入完整但越界"时给轻提示 (如红框/短提示)
- 删除 `cs-tapply` 按钮 + 其 click 绑定
- **保留 S1 的 ±60s 容差 + clamp** (改造中不得丢失)

### 2. 分段推进按钮
- 面板加 `◀ 上一段` / `下一段 ▶` (放在窗口标签旁)
- 语义: 步长 = **当前窗口长度** (结束-开始); `下一段` = [end, end+step], `上一段` = [start-step, start]
- 首次 (无上次窗口) 以当前滑块窗口为基准
- **边界**: 推进后超出 `[ts_first, ts_last]` → clamp 到素材边界并提示"已到末尾/开头"
  (不产生越界窗口, 不静默失败)

### 3. 状态持久化 (localStorage)
- 新增持久化键 (如 `zigbee.cubxPrescan`): `{ts_first, winStart, winEnd, inputs:{t1m..t2n}, subs:[...]}`
- **绑定素材**: `ts_first` 不匹配则丢弃旧值 (防串包, 沿用现有 `prev.prescan.ts_first===d.ts_first` 守卫)
- 子包清单同步持久化 (与 `S.cubxSubs` 双写: 内存供渲染, localStorage 供刷新恢复)
- 恢复时机: `reg()` 重建面板时 (行 258-262 现有恢复路径扩展)

### 4. 版本号
- `import.js` 改动 → `index.html` / `app.js` 版本号递增 (项目铁律, 否则用户刷不到新代码)

## 验证标准

1. 输入 8 格全满 → 自动生效 (窗口标签更新, 无需点按钮); 应用按钮已移除
2. 输满 2 位自动跳下一格; Enter 可立即应用
3. `下一段 ▶` : 5 分钟窗 → 点一次窗口整体后移 5 分钟; `◀ 上一段` 回退一致
4. 边界: 末段推进 → clamp + 提示, 不产生越界窗口
5. **切页验证**: 输入时间 + 选窗口 → 切到诊断页 → 回导入页 → 时间框/滑块/子包清单全部原样
6. **刷新验证**: F5 后同上 (**当前行为是会丢, 这是本次主要修复点**)
7. 换素材 (ts_first 不同) → 旧记忆被丢弃, 不串包
8. 非法输入 (13 月 / 32 日 / 25 时): 不崩溃、不误应用
9. 回归: S1 的 ±60s 容差 + clamp 仍生效 (起止输入面板显示的分钟值可正常应用);
   拆分流程 (拆分子包/下载/导入子包) 不受影响; 子包清单下载/导入按钮正常

## 风险

- localStorage 键与既有 state.js 机制的关系: 优先复用项目现有持久化惯例 (若无则新建, 命名统一)
- 自动应用可能与滑块 oninput 冲突 → 单向数据流约定清楚 (数字框 → 滑块, 滑块拖动不回写数字框,
  但推进按钮需回写两者)
- 子包清单体积: 记录数有限 (每段一条), 无膨胀风险; 但**子包文件被手工删除后清单仍显示** →
  列表标注"下载/导入失败时提示文件不存在"(沿用现有错误处理)
